<div class="tldr" markdown="1">
**Физическая организация ФС** — способ размещения файлов на диске. Единица обмена с диском — **сектор** (512 Б или 4 КБ). Единица выделения места файлу — **кластер (блок)**: группа секторов, например 4 КБ.

Способы размещения файла:
1. **Непрерывное (смежное)** — файл занимает подряд идущие кластеры. Быстро, но возникает внешняя фрагментация, файлу трудно расти (CD-ROM).
2. **Связный список кластеров** — каждый кластер хранит номер следующего.
3. **Связный список индексов (таблица FAT)** — цепочки номеров кластеров вынесены в отдельную таблицу.
4. **Перечень номеров кластеров (индексные узлы)** — для каждого файла хранится список его блоков: **inode** в UNIX (прямые и косвенные ссылки), **MFT** в NTFS (экстенты — серии кластеров).

Диск делится на **разделы**. Таблица разделов — **MBR** (до 4 основных разделов, до 2 ТБ) или **GPT** (до 128 разделов, огромные объёмы).
</div>

## Устройство диска

### Жёсткий диск (HDD)

- **Пластины** с магнитным покрытием, на каждой поверхности своя **головка**.
- **Дорожка** — концентрическая окружность на поверхности.
- **Цилиндр** — дорожки с одинаковым номером на всех поверхностях.
- **Сектор** — наименьшая адресуемая единица: 512 Б, в современных дисках 4096 Б («Advanced Format»).
- Адресация: раньше **CHS** (цилиндр, головка, сектор), сейчас **LBA** — сквозной номер сектора.
- Время доступа = **время поиска (перемещение головки)** + **задержка вращения** + время передачи. Поэтому на HDD важно, чтобы файл лежал **непрерывно** ([дефрагментация]({{ '/q/27.html' | relative_url }})).

### SSD

Флеш-память без движущихся частей. Время доступа не зависит от расположения данных. Ресурс записи ограничен, поэтому контроллер выполняет **выравнивание износа**, а ОС отправляет команду **TRIM**.

## Разделы и загрузка

- **Раздел (partition)** — непрерывная часть диска со своей ФС. После форматирования раздел становится **логическим диском (томом)**.
- **MBR (Master Boot Record)** — первый сектор диска: **загрузчик** и **таблица разделов** на 4 записи. Ограничения: до **4 основных** разделов (или 3 основных + **расширенный** с логическими дисками) и до **2 ТБ**.
- **GPT (GUID Partition Table)** — часть стандарта **UEFI**: до 128 разделов, размеры до зеттабайт, **резервная копия** таблицы в конце диска, контрольные суммы CRC.
- Управление в Windows: `diskpart`, оснастка «Управление дисками» (`diskmgmt.msc`). См. [команды]({{ '/cmd.html' | relative_url }}).

**Форматирование:**
- **низкоуровневое** — разметка секторов, выполняется на заводе;
- **высокоуровневое (логическое)** — создание структур ФС: загрузочного сектора, FAT или MFT, корневого каталога. Команда `format`.

## Кластеры

- **Кластер (блок, единица распределения)** — минимальная порция места, выделяемая файлу. Состоит из 2ⁿ секторов.
- **Большой кластер:** меньше служебных таблиц и быстрее работа с большими файлами, но **больше потерь** на маленьких файлах (внутренняя фрагментация: файл 1 байт занимает целый кластер).
- **Маленький кластер:** экономия места, но больше накладных расходов и фрагментации.
- Типичный размер в NTFS — **4 КБ**.

## Способы размещения файлов

### 1. Непрерывное размещение

Файл занимает **последовательные** кластеры. Достаточно знать **начальный кластер и длину**.

<pre class="diagram">
Кластеры: |A|A|A|B|B|·|·|C|C|C|C|·|
Каталог:  A: начало 0, длина 3
</pre>

- ➕ Просто, **максимальная скорость** последовательного и прямого доступа.
- ➖ **Внешняя фрагментация**, трудно увеличивать файл, нужно знать размер заранее.
- Применение: **CD/DVD (ISO 9660)**, где файлы не меняются.

### 2. Связный список кластеров

В каждом кластере хранится **номер следующего** кластера файла.
- ➕ Нет внешней фрагментации, файл легко растёт.
- ➖ **Прямой доступ медленный**: чтобы найти N-й кластер, надо прочитать все предыдущие.
- ➖ Объём данных в кластере не равен степени двойки, а повреждение одного кластера рвёт цепочку.

### 3. Таблица размещения файлов (FAT)

Номера следующих кластеров вынесены в **отдельную таблицу FAT** (File Allocation Table). Её размер равен числу кластеров на диске.

<pre class="diagram">
Каталог: report.txt → первый кластер 4

FAT:  индекс │ значение
      ───────┼─────────
         4   │   7
         7   │   2
         2   │  EOF  (конец файла)
         5   │   0   (свободен)
         9   │  BAD  (сбойный)

Файл report.txt: кластеры 4 → 7 → 2
</pre>

- Запись в каталоге содержит **имя, атрибуты, размер и номер первого кластера**.
- В FAT отмечаются **свободные** (0), **сбойные** (BAD) и **последние** (EOF) кластеры.
- **Две копии FAT** — для надёжности.
- ➕ Прямой доступ быстрее: цепочку можно пройти по таблице в памяти, не читая данные.
- ➖ Таблица велика для больших дисков, нет прав доступа и журнала, высокая фрагментация.
- Разновидности: **FAT12, FAT16, FAT32** (число означает разрядность номера кластера), exFAT.

### 4. Индексное размещение: inode (UNIX, ext2/3/4)

Каждому файлу соответствует **индексный дескриптор (inode)**. Он хранит **все атрибуты** (кроме имени) и **номера блоков** файла. **Каталог** содержит только пары «имя → номер inode».

<pre class="diagram">
inode
┌─────────────────────┐
│ тип, права, владелец│
│ размер, даты,       │
│ счётчик ссылок      │
├─────────────────────┤
│ 12 прямых ссылок ───┼─► блоки данных
│ однократно косв. ───┼─► блок адресов ─► данные
│ двукратно косв. ────┼─► … ─► … ─► данные
│ трёхкратно косв. ───┼─► … ─► … ─► … ─► данные
└─────────────────────┘
</pre>

- Маленькие файлы адресуются **прямыми** ссылками: быстро. Большие используют **косвенные** блоки.
- ext4 вместо списков блоков использует **экстенты** — диапазоны «начало, длина».
- Диск ext2: **суперблок**, **группы блоков** с битовыми картами блоков и inode, таблица inode и блоки данных.

### 5. NTFS: главная таблица файлов (MFT)

- **Всё есть файл**, включая служебные структуры: `$MFT`, `$LogFile` (журнал), `$Bitmap` (карта свободных кластеров), `$Boot`, `$Secure`…
- **MFT (Master File Table)** — таблица записей по **1 КБ**. На каждый файл отводится как минимум одна запись.
- Файл — набор **атрибутов**: `$STANDARD_INFORMATION`, `$FILE_NAME`, `$DATA` (данные), `$SECURITY_DESCRIPTOR` и другие.
- **Маленькие файлы** (до ~700 байт) хранятся **прямо в записи MFT** (резидентные атрибуты).
- Для больших файлов в записи хранится список **экстентов (отрезков, runs)**: «начальный кластер, число кластеров».
- Каталоги индексируются **B+-деревьями**, поэтому поиск быстрый.
- Копия первых записей MFT (`$MFTMirr`) повышает надёжность.

## Учёт свободного места

- **Битовая карта (bitmap):** 1 бит на кластер (0 — свободен, 1 — занят). Используется в NTFS и ext.
- **Список свободных блоков** (связный).
- **Значения в FAT** (0 = свободен).

## Сравнение способов

| Способ | Прямой доступ | Фрагментация | Пример |
|---|---|---|---|
| Непрерывный | Очень быстрый | Внешняя | ISO 9660 |
| Связный список | Медленный | Нет внешней | — |
| Таблица FAT | Средний | Нет внешней, но файлы разбросаны | FAT32 |
| Индексный (inode, MFT) | Быстрый | Нет внешней | ext4, NTFS |
