<div class="tldr" markdown="1">
При **сегментном распределении** виртуальное адресное пространство процесса делится на **сегменты** — **логически осмысленные части** программы **переменного размера**: код, данные, стек, куча, разделяемые библиотеки.

Виртуальный адрес задаётся парой **(номер сегмента, смещение)**. Для каждого процесса ведётся **таблица сегментов**. Каждый **дескриптор** содержит **базовый адрес** сегмента в физической памяти, **размер (предел)**, **права доступа**, признак присутствия.

Физический адрес = **база + смещение** при условии, что смещение < размера, иначе исключение.

➕ Соответствие логической структуре программы, удобная **защита** (код только для выполнения) и **разделение** сегментов между процессами. ➖ **Внешняя фрагментация**, так как сегменты переменного размера. Медленнее страниц: при подкачке перемещаются **целые сегменты**, нужна арифметика сложения.
</div>

## Идея

Программист мыслит не страницами, а **логическими частями**: «функция», «массив», «стек». Сегментация делает эти части отдельными **независимыми адресными пространствами**.

<pre class="diagram">
Процесс               Физическая память
                      ┌───────────────┐
сег. 0: код    ─────► │ 1400: код     │
                      ├───────────────┤
сег. 2: стек   ─────► │ 3200: стек    │
                      ├───────────────┤
сег. 1: данные ─────► │ 4300: данные  │
                      └───────────────┘
Сегменты лежат в памяти в любом
порядке, каждый — непрерывно.
</pre>

## Таблица сегментов

| № сегмента | База | Размер (предел) | Права | P |
|---|---|---|---|---|
| 0 (код) | 1400 | 1000 | чтение, выполнение | 1 |
| 1 (данные) | 4300 | 400 | чтение, запись | 1 |
| 2 (стек) | 3200 | 1100 | чтение, запись | 1 |
| 3 (библиотека) | — | 500 | выполнение | 0 (на диске) |

Кроме базы и размера, дескриптор может содержать признак **присутствия**, признак **обращения**, **модификации** и тип сегмента.

## Преобразование адреса

<pre class="diagram">
(сегмент s, смещение d)
        │
        ▼
 таблица сегментов[s] → (база, предел)
        │
   d < предел? ── нет ──► исключение
        │ да           (нарушение защиты)
        ▼
 физ. адрес = база + d
</pre>

**Пример** (по таблице выше):
- (1, 53) → 53 < 400 → физ. = 4300 + 53 = **4353**.
- (2, 1200) → 1200 ≥ 1100 → **ошибка: выход за границу сегмента**.
- (3, 10) → P = 0 → **сегментное прерывание**, ОС загружает сегмент с диска.

В отличие от страниц, база **складывается** со смещением, а не приписывается к нему. Нужен сумматор, а это чуть медленнее.

## Виртуальная память на основе сегментов

- В память загружаются только **нужные сегменты**. При обращении к отсутствующему сегменту (P = 0) возникает прерывание, ОС подгружает его, при нехватке места **выгружая** другой сегмент.
- Для размещения сегментов используются те же стратегии, что для [динамических разделов]({{ '/q/17.html' | relative_url }}): first fit, best fit.

## Защита и разделение

- **Защита:** у каждого сегмента свои права. Сегмент кода **нельзя изменить**, данные **нельзя выполнить**. Выход за предел ловится аппаратно.
- **Разделение (совместное использование):** несколько процессов могут ссылаться в своих таблицах на **один физический сегмент**. Например, код общей библиотеки или текстового редактора хранится в памяти один раз.

## Сегментация в x86

- В процессорах Intel сегментация была основным механизмом в 16-битном режиме: адрес = сегментный регистр × 16 + смещение. В защищённом режиме сегментные регистры (CS, DS, SS…) хранят **селекторы**, которые указывают на дескрипторы в таблицах **GDT/LDT**.
- Современные ОС (Windows, Linux) используют **плоскую модель**: все сегменты начинаются с 0 и имеют размер 4 ГБ, а реальная работа идёт на **страницах**. В режиме x86-64 сегментация почти отключена.

## Сравнение со страничной организацией

| | Страницы | Сегменты |
|---|---|---|
| Размер | Фиксированный (4 КБ) | Переменный |
| Определяется | Аппаратурой и ОС | Логикой программы, компилятором |
| Видна программисту | Нет | Да |
| Фрагментация | Внутренняя | **Внешняя** |
| Адрес | Номер страницы ‖ смещение (приписывание) | База + смещение (сложение) |
| Защита и разделение | По страницам | По логическим частям — естественнее |
| Перемещение при подкачке | Маленькие блоки | Целые сегменты (больше и дольше) |

## Достоинства и недостатки

- ➕ Соответствие **логической структуре** программы.
- ➕ Удобная **защита** и **разделение** кода и данных.
- ➕ Сегменты могут **независимо расти** (стек, куча).
- ➖ **Внешняя фрагментация**, может понадобиться сжатие.
- ➖ Перемещение больших сегментов при подкачке работает медленно.
- ➖ Размер сегмента ограничен размером физической памяти.

Решение недостатков — [сегментно-страничная организация]({{ '/q/20.html' | relative_url }}).
