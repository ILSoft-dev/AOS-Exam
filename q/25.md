<div class="tldr" markdown="1">
**Логическая организация ФС** — способ группировки файлов с помощью **каталогов (директорий)**. Каталог — это специальный файл, содержащий список файлов и подкаталогов.

Виды структур:
- **одноуровневая** — все файлы в одном каталоге (ранние ОС, CP/M);
- **двухуровневая** — у каждого пользователя свой каталог;
- **иерархическая — дерево:** у каждого файла **ровно один родительский каталог**, корень один (MS-DOS, FAT);
- **иерархическая — сеть (граф):** файл может входить в **несколько каталогов** благодаря **жёстким ссылкам** (UNIX, NTFS).

Имена файлов: **простое (короткое)** — `report.txt`; **полное (абсолютный путь)** — путь от корня, `C:\Docs\report.txt`, `/home/user/report.txt`; **относительное** — от текущего каталога, `..\img\a.png`.

Объединение нескольких ФС в одно дерево — **монтирование** (UNIX). В Windows используются **буквы дисков** или точки подключения.
</div>

## Каталог

**Каталог (директория, папка)** — файл особого типа. Он содержит **записи** о файлах: имя и (в зависимости от ФС) либо **атрибуты и адрес** данных (FAT), либо **ссылку на индексный дескриптор**, где хранятся атрибуты (inode в UNIX, запись MFT в NTFS).

Операции с каталогами: создать (`md`, `mkdir`), удалить (`rd`, `rmdir`), просмотреть (`dir`, `ls`), сменить текущий (`cd`), переименовать.

## Виды логической организации

### Одноуровневая

<pre class="diagram">
[корень]: a.txt  b.exe  c.doc  d.txt
</pre>
- Все файлы в одном списке, имена должны быть уникальны для всех пользователей.
- Неудобно при большом числе файлов.

### Двухуровневая

<pre class="diagram">
[корень]
 ├─ ivanov: a.txt  prog.c
 └─ petrov: a.txt  data.db
</pre>
- У каждого пользователя свой каталог. Одинаковые имена у разных пользователей допустимы.
- Нельзя группировать файлы внутри пользовательского каталога.

### Иерархическая: дерево

<pre class="diagram">
C:\
├─ Windows\
│  └─ System32\
│     └─ cmd.exe
├─ Users\
│  └─ Ivan\
│     ├─ Documents\
│     │  └─ report.docx
│     └─ Desktop\
└─ Program Files\
</pre>
- Каталоги могут содержать подкаталоги на любую глубину.
- **Один корень**, у каждого файла и каталога **один родитель**. Путь до файла **уникален**.
- Пример: MS-DOS, FAT.

### Иерархическая: сеть (ациклический граф)

- Файл может быть включён **в несколько каталогов**: у него несколько имён.
- Реализуется **жёсткими ссылками** (hard link) в UNIX и NTFS.
- Файл удаляется физически, только когда удалена **последняя** ссылка (в inode хранится **счётчик ссылок**).

## Имена файлов

| Вид | Пример | Пояснение |
|---|---|---|
| **Простое (краткое) имя** | `report.docx` | Уникально только в пределах каталога |
| **Полное (абсолютное) имя** | `C:\Users\Ivan\Documents\report.docx`, `/home/ivan/report.txt` | Цепочка каталогов **от корня**. Уникально в системе |
| **Относительное имя** | `Documents\report.docx`, `../img/logo.png` | Путь от **текущего** каталога |
| **Уникальный идентификатор** | Номер inode, номер записи MFT | Внутреннее «имя» для ОС |

Специальные имена: `.` — текущий каталог, `..` — родительский.

Ограничения имён: в **FAT** (MS-DOS) — формат **8.3** (8 символов имени + 3 расширения). В **FAT32 с VFAT** и **NTFS** — до **255 символов**, Unicode. В UNIX регистр символов **различается** (`File` ≠ `file`), в Windows по умолчанию нет.

## Ссылки

| | Жёсткая ссылка | Символическая (мягкая) ссылка |
|---|---|---|
| Что это | Ещё одна запись в каталоге, указывающая на **тот же** inode / запись MFT | Отдельный маленький файл, содержащий **путь** к цели |
| Если удалить оригинал | Данные остаются, пока есть хоть одна ссылка | Ссылка становится «битой» |
| Между разными ФС | Нельзя | Можно |
| На каталог | Обычно нельзя | Можно |
| UNIX | `ln a b` | `ln -s a b` |
| Windows | `mklink /H b a` | `mklink b a`, `mklink /D` (для каталога). Ещё есть **ярлыки .lnk** (уровень оболочки) и **точки соединения** `mklink /J` |

## Монтирование

В системе может быть несколько носителей и разделов, каждый со своей ФС.

- **Windows:** каждый том получает **букву диска** (`C:`, `D:`). Получается «лес» деревьев. Том можно подключить и в папку (точка подключения).
- **UNIX/Linux:** **единое дерево** с корнем `/`. Другие ФС **монтируются** в пустые каталоги: `mount /dev/sdb1 /mnt/usb`. После монтирования корень смонтированной ФС виден как каталог `/mnt/usb`. Список автоматического монтирования хранится в `/etc/fstab`.

<pre class="diagram">
/            (ФС на /dev/sda1)
├─ home/
├─ etc/
└─ mnt/
   └─ usb/   ← смонтирована /dev/sdb1
      └─ photo.jpg
</pre>
