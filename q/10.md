<div class="tldr" markdown="1">
**Прерывание** — сигнал, который заставляет процессор **приостановить выполнение текущей программы** и передать управление **обработчику прерывания**. После обработки, как правило, выполнение прерванной программы продолжается.

Назначение: **реакция на асинхронные события** (устройство завершило операцию, нажата клавиша, сработал таймер), обработка ошибок, вход в ОС. Прерывания — основа мультипрограммирования: без них ОС не узнаёт о завершении ввода-вывода и не может вытеснить поток по таймеру.

Три типа:
1. **Внешние (аппаратные)** — от устройств, **асинхронны** программе: таймер, клавиатура, диск, сеть.
2. **Внутренние (исключения)** — возникают при выполнении команды, **синхронны**: деление на ноль, страничный сбой, нарушение защиты, недопустимая команда.
3. **Программные** — специальная команда (`int`, `syscall`). Используется для **системных вызовов**.
</div>

## Зачем нужны прерывания

Альтернатива прерываниям — **опрос (polling)**: процессор постоянно проверяет флаг готовности устройства. Это тратит процессорное время впустую. С прерываниями процессор занимается полезной работой, а устройство само «сообщает», когда оно готово.

Прерывания используются для:
- обмена данными с устройствами ввода-вывода;
- **вытеснения потоков** по таймеру (разделение времени);
- обработки **ошибок и особых ситуаций**;
- реализации **системных вызовов**;
- реакции на **сбои оборудования** (питание, память).

## Типы прерываний

### 1. Внешние (аппаратные) прерывания

- Источник — **внешние устройства** через контроллер прерываний (PIC/APIC): таймер, клавиатура, мышь, диск, сетевая карта.
- **Асинхронны**: могут произойти в любой момент, между любыми двумя командами программы.
- Процессор проверяет наличие запроса **после завершения текущей команды**.
- Каждое устройство подключено к линии **IRQ**. Например, исторически в IBM PC IRQ0 — таймер, IRQ1 — клавиатура.
- Среди них выделяют **немаскируемые (NMI)** — критические: сбой памяти, падение питания. Их нельзя запретить.

### 2. Внутренние прерывания (исключения, exceptions)

- Возникают **синхронно** с выполнением программы, при выполнении конкретной команды.
- Виды:
  - **Ошибки (faults)** — обработчик исправляет ситуацию, и **команда выполняется повторно**. Пример — **страничный сбой (page fault)**: страница загружается с диска, команда повторяется.
  - **Ловушки (traps)** — обработка выполняется после команды, и программа продолжается со следующей команды (точки останова отладчика, пошаговый режим).
  - **Аварийные завершения (aborts)** — неустранимые ошибки, процесс обычно завершается.
- Примеры: деление на ноль, переполнение, обращение к запрещённому адресу (**нарушение защиты памяти**), недопустимый код операции, попытка выполнить привилегированную команду в пользовательском режиме.

### 3. Программные прерывания

- Вызываются **специальной командой процессора**: `INT n` в x86, `SYSCALL`/`SYSENTER` в современных процессорах.
- По сути это не «настоящее» прерывание, а **удобный способ вызвать процедуру ОС с переходом в привилегированный режим**.
- Используются для **системных вызовов** ([вопрос 4]({{ '/q/04.html' | relative_url }})). Например, `INT 21h` в MS-DOS и `INT 80h` в старом Linux.
- Синхронны: происходят ровно там, где стоит команда.

## Сравнение

| | Внешние | Внутренние (исключения) | Программные |
|---|---|---|---|
| Источник | Устройства (таймер, I/O) | Ошибка или особая ситуация при выполнении команды | Команда `INT`/`SYSCALL` |
| Синхронность | Асинхронные | Синхронные | Синхронные |
| Пример | Нажатие клавиши, конец чтения диска | Деление на 0, page fault | Системный вызов |
| Можно ли замаскировать | Да (кроме NMI) | Нет | Нет |

## Приоритеты и маскирование

- Прерывания имеют **приоритеты**. Обработчик низкоприоритетного прерывания может быть прерван более приоритетным (**вложенные прерывания**). В Windows эти уровни называются **IRQL** (Interrupt Request Level).
- **Маскирование** — временный запрет определённых прерываний, например на время работы с критическими структурами ядра. Немаскируемые прерывания (NMI) запретить нельзя.
- Типичный порядок приоритета: аппаратные сбои → таймер → диски → сеть → терминалы → программные прерывания.

## Таблица векторов прерываний

Каждому типу прерывания соответствует **номер (вектор)**. По номеру процессор находит адрес обработчика в **таблице векторов прерываний** (IVT в реальном режиме, **IDT** в защищённом режиме x86). Например, вектор 0 — деление на ноль, 14 — страничный сбой.
