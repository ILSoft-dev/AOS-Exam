<div class="tldr" markdown="1">
**Файл** — именованная область данных на внешнем носителе. **Файловая система (ФС)** — часть ОС, которая включает:
- совокупность **всех файлов** на дисках;
- **служебные структуры** для управления файлами: каталоги, дескрипторы файлов, таблицы распределения свободного и занятого места;
- **программные средства**, которые реализуют операции над файлами: создание, удаление, чтение, запись, именование, поиск, защиту.

**Цели и задачи ФС:**
- **именование** файлов (символьные имена вместо адресов на диске);
- **программный интерфейс** для приложений;
- **отображение** логической модели (файлы, каталоги) на **физическую** организацию носителя;
- **устойчивость** к сбоям и **защита** от несанкционированного доступа;
- **совместный доступ** нескольких пользователей и процессов;
- **эффективность** — быстрый доступ, экономия места.
</div>

## Зачем нужна файловая система

Диск — это просто массив **блоков (секторов)**, пронумерованных от 0 до N. Без ФС программисту пришлось бы помнить, в каких секторах лежат его данные. ФС предоставляет удобную абстракцию **«файл в каталоге с именем»**.

## Цели файловой системы

1. **Именование** — пользователь обращается к данным по символьному имени (`C:\Docs\report.docx`).
2. **Программный интерфейс** — набор системных вызовов (`open`, `read`, `CreateFile`…).
3. **Отображение логической модели на физическую** — ФС решает, в каких блоках диска лежит файл.
4. **Устойчивость к сбоям** — защита от потери данных при сбоях питания и аппаратуры ([вопросы 29–31]({{ '/q/29.html' | relative_url }})).
5. **Совместное использование** — несколько процессов работают с файлами одновременно. Нужны **блокировки** (файлов и отдельных записей).
6. **Защита** — разграничение прав доступа ([вопрос 28]({{ '/q/28.html' | relative_url }})).
7. **Производительность** — кеширование, оптимальное размещение блоков.

## Задачи ОС по управлению файлами и устройствами

Эти задачи из программы курса (тема 2) решает в первую очередь ФС вместе с **подсистемой ввода-вывода**:
- организация **параллельной работы** устройств ввода-вывода и процессора;
- **согласование скоростей** обмена и **кеширование** данных;
- **разделение** устройств и данных между процессами;
- удобный **логический интерфейс** между устройствами и системой;
- поддержка широкого спектра **драйверов** и **нескольких ФС** одновременно.

## Типы файлов

- **Обычные файлы** — текстовые и двоичные: документы, программы.
- **Каталоги (директории)** — специальные файлы, которые содержат списки других файлов и их атрибуты или ссылки на них.
- **Специальные файлы** (в UNIX) — устройства: `/dev/sda`, `/dev/null`. Работа с устройствами через файловый интерфейс.
- **Именованные каналы (FIFO)**, сокеты, **символические ссылки**.

## Атрибуты файлов

Кроме имени и данных, файл имеет **атрибуты (метаданные)**:
- **тип** и **размер**;
- **владелец** и **права доступа**;
- **даты**: создания, последнего изменения, последнего доступа;
- флаги: **только чтение**, **скрытый**, **системный**, **архивный**, **сжатый**, **зашифрованный**;
- **местоположение** данных на диске.

В Windows атрибуты меняют командой `attrib`, в Linux права меняют через `chmod` и `chown`.

## Логическая организация файла

- **Последовательность байтов (неструктурированный файл)** — ОС не интерпретирует содержимое (UNIX, Windows).
- **Последовательность записей** фиксированной или переменной длины (старые мейнфреймы).
- **Индексированный файл** — записи с ключами (как в СУБД).

**Способы доступа:** **последовательный** (как лента) и **прямой (произвольный)** — по номеру байта или записи (`lseek`, `SetFilePointer`).

## Файловые операции

| Операция | UNIX | Windows |
|---|---|---|
| Создать | `creat`, `open(O_CREAT)` | `CreateFile` |
| Открыть / закрыть | `open` / `close` | `CreateFile` / `CloseHandle` |
| Читать / писать | `read` / `write` | `ReadFile` / `WriteFile` |
| Позиционировать | `lseek` | `SetFilePointer` |
| Получить атрибуты | `stat` | `GetFileAttributes` |
| Переименовать / удалить | `rename` / `unlink` | `MoveFile` / `DeleteFile` |

**Зачем открывать файл?** При **открытии** ОС один раз ищет файл в каталогах, проверяет права и создаёт запись в **таблице открытых файлов**. Затем процесс получает **дескриптор** (число в UNIX, HANDLE в Windows). Последующие операции используют дескриптор и не повторяют поиск.

## Примеры файловых систем

| ФС | ОС | Особенности |
|---|---|---|
| **FAT12/16/32** | MS-DOS, Windows, флешки | Простая, таблица FAT. В FAT32 файл до 4 ГБ, нет прав доступа и журнала |
| **exFAT** | Флешки, SD-карты | Большие файлы, простая структура |
| **NTFS** | Windows | MFT, ACL-права, журналирование, сжатие, шифрование (EFS), квоты |
| **ReFS** | Windows Server | Устойчивость к повреждениям, контрольные суммы |
| **ext2/3/4** | Linux | Индексные дескрипторы (inode), ext3 и ext4 — журналируемые |
| **XFS, Btrfs, ZFS** | Linux, UNIX | Большие объёмы, снимки (snapshot), контрольные суммы |
| **APFS** | macOS, iOS | Копирование при записи, шифрование |
| **ISO 9660, UDF** | CD, DVD | |
| **NFS, SMB/CIFS** | Сеть | [Вопрос 36]({{ '/q/36.html' | relative_url }}) |
