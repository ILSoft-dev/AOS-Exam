<div class="tldr" markdown="1">
**Процесс** — выполняемая программа вместе с выделенными ей ресурсами: **виртуальным адресным пространством**, открытыми файлами, дескрипторами и правами. Процесс — **единица владения ресурсами**.

**Поток (нить, thread)** — последовательность выполнения команд внутри процесса. У потока есть только **свой счётчик команд, регистры и стек**. Поток — **единица планирования** процессорного времени. Все потоки процесса разделяют его память и ресурсы.

Состояния потока: **выполнение**, **готовность**, **ожидание (блокировка)**.

**Создание процесса:** ОС создаёт **дескриптор (PCB)** и **контекст**, выделяет адресное пространство, загружает код и создаёт первый (главный) поток. **Создание потока** дешевле: нужны только дескриптор потока, стек и контекст. Функции создания: `CreateProcess`/`CreateThread` в Windows, `fork`+`exec`/`pthread_create` в UNIX.
</div>

## Процесс

ОС рассматривает процесс как **заявку на потребление ресурсов**. Каждый процесс получает:
- изолированное **виртуальное адресное пространство** (код, данные, куча, стеки);
- **открытые файлы**, сокеты и другие объекты;
- **идентификатор (PID)**, владельца и права доступа;
- как минимум **один поток**.

### Дескриптор и контекст процесса

- **Дескриптор процесса (PCB, Process Control Block)** — структура ядра с информацией, нужной ОС **всегда**: идентификатор, состояние, приоритет, указатель на таблицу страниц, список ресурсов, родитель. В Windows это структура `EPROCESS`, в Linux — `task_struct`.
- **Контекст** — информация, нужная только **для возобновления выполнения**: содержимое регистров процессора, счётчик команд (PC), указатель стека, флаги, состояние сопроцессора.

Пример дескриптора процесса:

| Поле PCB | Пример |
|---|---|
| PID, PPID | 4312, 1 |
| Состояние | Готов |
| Приоритет | 8 |
| Регистры (контекст) | PC = 0x401A20, SP = … |
| Таблица страниц | адрес |
| Открытые файлы | 0: stdin, 1: stdout, 3: data.txt |
| Учёт ресурсов | время ЦП, память |

## Поток

Потоки появились, чтобы **распараллелить работу внутри одного приложения** без дорогих процессов. Например, в текстовом редакторе один поток принимает ввод, другой проверяет орфографию, третий автосохраняет.

| | Процесс | Поток |
|---|---|---|
| Что это | Контейнер ресурсов | Единица выполнения (планирования) |
| Адресное пространство | Своё, изолированное | Общее с другими потоками процесса |
| Своё у каждого | Память, файлы, PID | Регистры, счётчик команд, **стек**, TID, локальная память потока (TLS) |
| Создание и переключение | Дорого | Дёшево |
| Обмен данными | Через IPC (каналы, сокеты, разделяемая память) | Напрямую через общую память, но нужна синхронизация |
| Сбой | Не затрагивает другие процессы | Может обрушить весь процесс |

### Потоки пользовательского уровня и уровня ядра

- **Потоки ядра:** ОС знает о каждом потоке и планирует его. Блокировка одного потока не останавливает остальные, и потоки могут работать на разных ядрах. Так работают Windows и Linux.
- **Пользовательские потоки:** реализуются библиотекой. Ядро видит только процесс. Переключение очень быстрое, но блокирующий системный вызов останавливает все потоки процесса.
- **Модели отображения:** «многие к одному», «один к одному» (Windows, Linux) и «многие ко многим».

## Состояния потока

<pre class="diagram">
   создание
      │
      ▼    выбран планировщиком
 ┌─────────┐ ─────────────► ┌────────────┐
 │ ГОТОВ-  │                │ ВЫПОЛНЕНИЕ │
 │  НОСТЬ  │ ◄───────────── │            │
 └─────────┘ квант истёк /  └────────────┘
      ▲      вытеснен            │    │
      │                 ждёт I/O,│    │ завершение
      │                 ресурса  ▼    ▼
      │  событие      ┌──────────┐  конец
      └───────────────│ ОЖИДАНИЕ │
        произошло     └──────────┘
</pre>

- **Выполнение** — поток выполняется процессором. На одном ядре в этом состоянии может быть только один поток.
- **Готовность** — потоку не хватает только процессора, он стоит в **очереди готовых потоков**.
- **Ожидание (блокировка)** — поток ждёт события: завершения ввода-вывода, освобождения ресурса, сигнала.

Часто выделяют ещё состояния **«создание»** и **«завершение»** (зомби в UNIX). Из ожидания поток переходит **только в готовность**, а не сразу в выполнение.

## Очереди

ОС хранит дескрипторы потоков в **очередях**: очередь готовых потоков (часто отдельная для каждого приоритета) и очереди ожидания для каждого ресурса или события. Планировщик выбирает поток из очереди готовых. Об организации очередей см. [вопросы 7–9]({{ '/q/07.html' | relative_url }}).

## Создание процессов и потоков

**Шаги создания процесса:**
1. Создать дескриптор процесса (PCB) и присвоить идентификатор.
2. Выделить **адресное пространство** и построить таблицу страниц.
3. Загрузить код и данные программы из исполняемого файла (`.exe`, ELF).
4. Выделить ресурсы: открытые файлы и наследуемые дескрипторы.
5. Создать **первый (главный) поток**: его дескриптор, стек и контекст. Поставить поток в очередь готовых.

**Шаги создания потока:** создать дескриптор потока, выделить стек, сформировать начальный контекст (PC = адрес функции потока), поставить в очередь готовых. Адресное пространство не создаётся, поэтому это **гораздо быстрее**.

### Windows

```c
// новый процесс
STARTUPINFO si = { sizeof si };
PROCESS_INFORMATION pi;
CreateProcess(L"C:\\Windows\\notepad.exe", NULL, NULL, NULL,
              FALSE, 0, NULL, NULL, &si, &pi);

// новый поток
DWORD WINAPI Worker(LPVOID arg) { /* работа */ return 0; }
HANDLE h = CreateThread(NULL, 0, Worker, NULL, 0, NULL);
WaitForSingleObject(h, INFINITE);
```

### UNIX / Linux (POSIX)

```c
pid_t pid = fork();            // копия процесса
if (pid == 0) {                // потомок
    execlp("ls", "ls", "-l", NULL);  // заменить программу
} else {
    waitpid(pid, NULL, 0);     // родитель ждёт
}

// поток
void *worker(void *arg) { return NULL; }
pthread_t t;
pthread_create(&t, NULL, worker, NULL);
pthread_join(t, NULL);
```

В C# поток создаётся через `new Thread(Method).Start()`, а процесс — через `Process.Start("notepad.exe")`.

**Иерархия:** в UNIX процессы образуют **дерево** (родитель → потомки, корень — `init`/`systemd`). В Windows иерархия формальная, процессы в основном равноправны.
