<div class="tldr" markdown="1">
**Гипервизор второго типа (hosted, «размещённый»)** работает как **обычное приложение поверх хостовой ОС** (Windows, Linux, macOS). Для доступа к оборудованию он использует **драйверы и службы хостовой ОС**. Обычно он устанавливает и свой драйвер (модуль ядра), чтобы использовать аппаратную виртуализацию VT-x / AMD-V.

<pre class="diagram">
ВМ (гостевая ОС) │ ВМ │ обычные прил.
─────────────────┴────┤
 Гипервизор тип 2     │
──────────────────────┴───────────
 Хостовая ОС (Windows/Linux/macOS)
──────────────────────────────────
 Оборудование
</pre>

- ➕ **Простота установки и использования** (как обычной программы), работа на **обычном ПК** рядом с другими приложениями, широкая поддержка оборудования через хостовую ОС, удобный обмен файлами и буфером обмена.
- ➖ **Ниже производительность** (лишний уровень — хостовая ОС), **зависимость от хостовой ОС**: её сбой или обновление затрагивает все ВМ. Меньше изоляция и безопасность.
- Применение: **рабочие станции разработчиков**, тестирование, **обучение**, запуск программ другой ОС.
- Примеры: **Oracle VirtualBox**, **VMware Workstation / Player / Fusion**, **Parallels Desktop**, **QEMU** (в режиме эмуляции).
</div>

## Архитектура и принцип работы

Гипервизор второго типа обычно состоит из:
- **пользовательского приложения** — интерфейс, настройки ВМ, эмуляция устройств;
- **драйвера (модуля ядра) хостовой ОС** — переключает процессор в режим выполнения гостя, использует **VT-x / AMD-V**, управляет памятью ВМ.

Когда гостевой код выполняется, процессор работает **напрямую** в режиме гостя. При обращении к устройствам (диск, сеть, видео) происходит **выход в гипервизор**. Гипервизор **эмулирует** устройство и выполняет операцию через **обычные вызовы хостовой ОС**: чтение файла виртуального диска, сетевой сокет.

### Виртуальные устройства

- **Виртуальный диск** — файл на хостовой ФС: `.vdi` (VirtualBox), `.vmdk` (VMware), `.vhd/.vhdx` (Hyper-V), `.qcow2` (QEMU). Бывает **фиксированного размера** или **динамически расширяемым**.
- **Сеть:** NAT, сетевой мост (bridged), внутренняя сеть, «только хост» (host-only).
- **Дополнения гостевой ОС** (VirtualBox Guest Additions, VMware Tools) — **паравиртуальные драйверы** для ускорения видео, сети, общих папок и буфера обмена ([вопрос 39]({{ '/q/39.html' | relative_url }})).
- **Снимки (snapshots)** — сохранение состояния ВМ с возможностью отката.

## Достоинства и недостатки

| ➕ Достоинства | ➖ Недостатки |
|---|---|
| Устанавливается как обычная программа, не нужен отдельный сервер | Производительность ниже, чем у типа 1: накладные расходы хостовой ОС |
| Работает на обычном ПК или ноутбуке | ВМ конкурируют за ресурсы с программами пользователя |
| Поддерживает любое оборудование, которое поддерживает хостовая ОС | Зависимость от хостовой ОС: сбой, перезагрузка или обновление хоста останавливает все ВМ |
| Удобная интеграция: общие папки, буфер обмена, drag & drop | Больше поверхность атаки: уязвимость хостовой ОС угрожает всем ВМ |
| Часто бесплатны (VirtualBox, VMware Player, QEMU) | Не подходит для промышленных серверных нагрузок |

## Примеры

| Продукт | Хостовые ОС | Особенности |
|---|---|---|
| **Oracle VirtualBox** | Windows, Linux, macOS (Intel) | Бесплатный, открытый, кроссплатформенный |
| **VMware Workstation Pro / Player** | Windows, Linux | Профессиональные функции, сейчас бесплатен для личного использования |
| **VMware Fusion** | macOS | |
| **Parallels Desktop** | macOS | Интеграция с macOS, запуск Windows на Mac (в том числе на Apple Silicon) |
| **QEMU** | Linux, Windows, macOS | Может **эмулировать другие архитектуры** (ARM на x86). Вместе с KVM даёт аппаратную виртуализацию |

## Эмуляция и виртуализация

- **Виртуализация** — гостевой код выполняется **напрямую** на процессоре той же архитектуры. Это быстро.
- **Эмуляция** — каждая команда гостя **интерпретируется или транслируется** программно. Позволяет запускать код **другой архитектуры** (например, ARM-программы на x86), но во много раз медленнее. Примеры: QEMU в режиме TCG, эмуляторы игровых консолей, эмулятор Android.

## Особые случаи

- **Вложенная виртуализация** — запуск гипервизора внутри ВМ. Используется для тестирования и обучения.
- **Сосуществование с Hyper-V:** если в Windows включён Hyper-V (или WSL2, «Песочница»), то Windows уже работает поверх гипервизора типа 1. Тогда VirtualBox и VMware Workstation используют **Windows Hypervisor Platform API**.
- **WSL2** (Windows Subsystem for Linux) запускает настоящее ядро Linux в лёгкой ВМ Hyper-V.

## Сравнение типов гипервизоров

| Критерий | Тип 1 | Тип 2 |
|---|---|---|
| Где работает | На оборудовании | Поверх хостовой ОС |
| Производительность | Высокая | Ниже |
| Изоляция и безопасность | Выше | Ниже |
| Установка | Как ОС, на выделенный сервер | Как приложение |
| Типичное применение | Серверы, ЦОД, облака | Рабочие станции, тесты, обучение |
| Примеры | ESXi, Hyper-V, Xen, KVM | VirtualBox, VMware Workstation, Parallels |
