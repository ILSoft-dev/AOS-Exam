<div class="tldr" markdown="1">
При **страничном распределении** виртуальное адресное пространство процесса делится на **виртуальные страницы** одинакового размера (обычно **4 КБ**, степень двойки). Физическая память делится на **физические страницы (кадры, фреймы)** того же размера.

Для каждого процесса ОС ведёт **таблицу страниц**: номер виртуальной страницы → номер физической страницы + **признак присутствия**, биты **обращения**, **модификации**, **защиты**.

Виртуальный адрес = **(номер страницы, смещение)**. MMU находит номер кадра в таблице и приписывает к нему смещение. Если страницы нет в памяти (бит присутствия = 0), возникает **страничное прерывание (page fault)**. ОС загружает страницу с диска, при нехватке места **вытесняя** другую страницу (алгоритмы **FIFO, LRU, NRU, «часы», OPT**).

➕ Нет внешней фрагментации, процесс может быть больше ОЗУ. ➖ Внутренняя фрагментация (полстраницы в среднем), затраты на таблицы. Ускорение — кеш преобразований **TLB**.
</div>

## Принцип

<pre class="diagram">
Таблица страниц процесса
┌──────┬───────┬───┐
│ вирт │ кадр  │ P │
├──────┼───────┼───┤
│  0   │   5   │ 1 │ → кадр 5 в ОЗУ
│  1   │   –   │ 0 │ → на диске
│  2   │   2   │ 1 │ → кадр 2 в ОЗУ
│  3   │   7   │ 1 │ → кадр 7 в ОЗУ
└──────┴───────┴───┘
P — признак присутствия в памяти
</pre>

- Страницы процесса в физической памяти могут лежать **в любых кадрах, не подряд**. Поэтому нет внешней фрагментации.
- В памяти в каждый момент находится только **часть** страниц процесса. Остальные хранятся на диске (в файле подкачки).

## Запись таблицы страниц (дескриптор страницы)

| Поле | Назначение |
|---|---|
| **Номер физической страницы (кадра)** | Куда отображена страница |
| **P — признак присутствия** | 1 — страница в ОЗУ, 0 — на диске |
| **R — признак обращения (Accessed)** | Устанавливается при любом обращении. Нужен алгоритмам замещения |
| **M — признак модификации (Dirty)** | Страница изменена, при вытеснении её нужно записать на диск |
| **Права доступа** | Чтение, запись, выполнение, пользователь/ядро |

## Преобразование виртуального адреса в физический

Размер страницы — степень двойки, поэтому адрес делится на поля **без вычислений**:

<pre class="diagram">
Виртуальный адрес (32 бита, стр. 4 КБ = 2¹²)
┌──────────────────────┬────────────┐
│ номер страницы (20 б)│ смещение 12│
└──────────┬───────────┴─────┬──────┘
           ▼ таблица страниц │
       номер кадра           │
           ▼                 ▼
┌──────────────────────┬────────────┐
│     номер кадра      │ смещение   │
└──────────────────────┴────────────┘
Физический адрес
</pre>

**Пример.** Страница 4 КБ = 4096 байт. Виртуальный адрес **8200**.
- Номер страницы = 8200 div 4096 = **2**, смещение = 8200 mod 4096 = **8**.
- По таблице страница 2 → кадр **5**.
- Физический адрес = 5 × 4096 + 8 = **20 488**.

## Страничное прерывание (page fault)

1. MMU обнаруживает, что бит присутствия P = 0, и генерирует **исключение**.
2. ОС приостанавливает поток (он переходит в ожидание).
3. ОС находит **свободный кадр**. Если его нет, выбирает **страницу-жертву** по алгоритму замещения. Если у жертвы M = 1, её содержимое **записывается на диск**.
4. Нужная страница **считывается с диска** в кадр, таблица страниц обновляется (P = 1).
5. Поток возвращается в готовность, и **прерванная команда выполняется повторно**.

Это **подкачка по требованию (demand paging)**: страницы загружаются, только когда к ним обратились.

## Алгоритмы замещения страниц

| Алгоритм | Какую страницу вытесняет | Комментарий |
|---|---|---|
| **OPT (оптимальный, Белади)** | Ту, к которой обратятся **позже всех** в будущем | Нереализуем (будущее неизвестно), используется как эталон |
| **FIFO** | Загруженную **раньше всех** | Прост, но может вытеснить часто используемую страницу. **Аномалия Белади:** больше кадров иногда даёт больше сбоев |
| **LRU (Least Recently Used)** | Ту, к которой **дольше всего не обращались** | Близок к OPT, но дорог в точной реализации |
| **NRU (Not Recently Used)** | По битам R и M: сначала класс (R=0, M=0), затем (0,1), (1,0), (1,1) | Биты R периодически сбрасываются по таймеру |
| **«Часы» (Clock, вторая попытка)** | Идёт по кругу: если R = 1, сбрасывает R и идёт дальше, если R = 0 — вытесняет | Хорошее приближение LRU, широко применяется |
| **LFU** | Ту, к которой обращались **реже всего** | |

**Пример (3 кадра, обращения 1 2 3 4 1 2 5 1 2 3 4 5):**
- **FIFO:** 9 страничных прерываний.
- **LRU:** 10 страничных прерываний.
- **OPT:** 7 страничных прерываний.

(Это известная строка для аномалии Белади: в FIFO с 4 кадрами получается 10 сбоев, то есть **больше**, чем с 3.)

## Размер страницы: компромисс

- **Маленькие страницы:** меньше внутренняя фрагментация, точнее подгружается нужное. Но **таблицы больше** и больше страничных прерываний.
- **Большие страницы:** меньше таблицы и эффективнее обмен с диском. Но больше потерь внутри страницы.
- Типично **4 КБ**. Для серверов и баз данных используют «большие страницы» по 2 МБ и 1 ГБ.

## Проблемы и их решения

### Размер таблицы страниц → многоуровневые таблицы

32-битное пространство при странице 4 КБ = 2²⁰ ≈ 1 млн записей по 4 байта = **4 МБ на процесс**. Решение — **многоуровневые (иерархические) таблицы**: адрес делится на индекс каталога, индекс таблицы и смещение (x86: 10 + 10 + 12 бит). В памяти хранятся только нужные таблицы второго уровня. В x86-64 используются **4–5 уровней**.

### Скорость → TLB

Каждое обращение к памяти требует ещё обращения к таблице страниц, а то и нескольких. **TLB (Translation Lookaside Buffer, буфер ассоциативной трансляции)** — маленький быстрый **ассоциативный кеш** в процессоре, который хранит последние преобразования «страница → кадр». Попадание в TLB достигает 98–99 %.

## Достоинства и недостатки

- ➕ **Нет внешней фрагментации**, не нужно сжатие.
- ➕ Процесс может быть **больше физической памяти**, загружаются только нужные страницы.
- ➕ Простое разделение и защита на уровне страниц.
- ➖ **Внутренняя фрагментация** — в среднем полстраницы на процесс (на сегмент).
- ➖ Накладные расходы на таблицы и страничные прерывания.
- ➖ Страница — **механическая** единица, она не соответствует логической структуре программы (код, данные, стек). Эту проблему решает сегментация.
- ⚠️ **Пробуксовка (thrashing):** если памяти слишком мало для рабочих множеств, система почти всё время занята подкачкой.
