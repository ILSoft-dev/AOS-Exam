<div class="tldr" markdown="1">
ОС состоит из **ядра** и **вспомогательных модулей**. Ядро работает в **привилегированном режиме (режиме ядра)** и выполняет базовые функции: управляет процессами, памятью, вводом-выводом и файлами. Вспомогательные модули — это утилиты, системные обрабатывающие программы, библиотеки и оболочка. Они работают в **пользовательском режиме**, как обычные приложения.

Основные варианты построения: **монолитная** система, **многоуровневая (слоистая)**, **микроядерная**, **гибридная**, а также экзоядро и модель виртуальных машин. Внутри ядро делится на слои: средства аппаратной поддержки → машинно-зависимые компоненты (HAL) → базовые механизмы → менеджеры ресурсов → интерфейс системных вызовов.
</div>

## Ядро и вспомогательные модули

| Часть ОС | Что входит | Режим работы |
|---|---|---|
| **Ядро** | Управление процессами и потоками, планировщик, управление памятью, файловая система, драйверы (в монолите), обработка прерываний, системные вызовы | Режим ядра (привилегированный) |
| **Вспомогательные модули** | **Утилиты** (дефрагментация, архивация, проверка диска), **системные обрабатывающие программы** (компиляторы, отладчики, текстовые редакторы), **библиотеки** (libc, kernel32.dll), **оболочка** (cmd, bash, Explorer) | Пользовательский режим |

Функции ядра вызываются часто, поэтому ядро обычно постоянно находится в оперативной памяти (**резидентно**). Вспомогательные модули загружаются по необходимости.

## Привилегированный режим

Процессор поддерживает минимум два режима:

- **Режим ядра (kernel mode, ring 0)** разрешает любые инструкции: работу с портами ввода-вывода, изменение таблиц страниц, запрет прерываний.
- **Пользовательский режим (user mode, ring 3)**: привилегированные инструкции запрещены, доступна только своя память.

Приложение не может напрямую повредить ядро или другие приложения. Чтобы получить услугу ядра, оно выполняет **системный вызов** (см. [вопрос 4]({{ '/q/04.html' | relative_url }})).

## Многослойная структура ядра

<pre class="diagram">
┌──────────────────────────────┐
│  Интерфейс системных вызовов │
├──────────────────────────────┤
│  Менеджеры ресурсов          │
│  (процессы, память, ФС, I/O) │
├──────────────────────────────┤
│  Базовые механизмы ядра      │
│  (переключение контекста,    │
│   работа с таблицами стр.)   │
├──────────────────────────────┤
│  Машинно-зависимые модули    │
│  (HAL)                       │
├──────────────────────────────┤
│  Средства аппаратной         │
│  поддержки ОС                │
└──────────────────────────────┘
          Аппаратура
</pre>

1. **Средства аппаратной поддержки ОС** — часть «железа»: система прерываний, средства поддержки режимов, защиты памяти, таймер, переключение контекста.
2. **Машинно-зависимые компоненты (HAL, Hardware Abstraction Layer)** скрывают особенности конкретной платформы. Они нужны для **переносимости** ОС.
3. **Базовые механизмы ядра** выполняют простейшие операции: переключение контекстов процессов, диспетчеризацию прерываний, перемещение страниц между памятью и диском. Они не принимают решений («механизм, а не политика»).
4. **Менеджеры ресурсов** реализуют стратегии управления процессами, памятью, файлами и вводом-выводом. Они решают, *кому и когда* выделить ресурс.
5. **Интерфейс системных вызовов** (API) — верхний слой, через который приложения обращаются к ядру.

## Архитектурные модели ОС

### Монолитная система

Всё ядро — **одна большая программа** в адресном пространстве ядра. Любая процедура может вызвать любую другую.
- ➕ Высокая скорость: нет переключений режимов внутри ядра.
- ➖ Ошибка в любом драйвере может «уронить» всю систему, ядро сложно сопровождать.
- Примеры: классический UNIX, **Linux** (монолит с загружаемыми модулями), MS-DOS.

### Многоуровневая (слоистая) система

Ядро разбито на **иерархию слоёв**. Каждый слой использует только функции нижележащего слоя.
- ➕ Легко отлаживать и проверять: слои тестируются по отдельности.
- ➖ Потери производительности на переходах между слоями, сложно правильно распределить функции по слоям.
- Примеры: **THE** (Дейкстра, 1968), MULTICS (кольца защиты).

### Микроядерная архитектура

В режиме ядра работает только **минимальное микроядро**: управление адресными пространствами, потоками и прерываниями и **механизм обмена сообщениями (IPC)**. Файловые системы, драйверы и сетевой стек вынесены в **серверы**, которые работают в пользовательском режиме.
- ➕ Надёжность (сбой драйвера не роняет ядро), расширяемость, переносимость, удобство для распределённых систем.
- ➖ Ниже производительность из-за частых переключений режимов и передачи сообщений.
- Примеры: **Mach**, **QNX**, MINIX 3, L4.

### Гибридная (смешанная) архитектура

Сочетает подходы: структура как у микроядра, но для скорости многие сервисы работают в режиме ядра.
- Примеры: **Windows NT/10/11** (микроядро + исполнительная система + HAL в режиме ядра), **macOS (XNU = Mach + BSD)**.

### Другие модели

- **Экзоядро** только безопасно распределяет ресурсы. Абстракции реализуются в библиотеках приложений.
- **Модель виртуальных машин** — каждая программа работает на своей «копии» машины (IBM VM/370, современные гипервизоры, [вопросы 37–40]({{ '/q/37.html' | relative_url }})).
- **Клиент-серверная модель** — частный случай микроядра: приложения (клиенты) запрашивают услуги у серверов ОС через ядро.

## Требования к современной ОС

**Расширяемость, переносимость, надёжность и отказоустойчивость, совместимость, безопасность, производительность.** Структура ОС выбирается как компромисс между ними. Например, микроядро даёт надёжность и расширяемость, а монолит — производительность.
