<div class="tldr" markdown="1">
**Потоки одного процесса** работают в **общем адресном пространстве** и обмениваются данными **напрямую** через общие переменные. Нужна только **синхронизация** (мьютексы, семафоры, события).

**Процессы изолированы** друг от друга, поэтому ОС предоставляет средства **межпроцессного взаимодействия (IPC)**:
- **разделяемая память** (в том числе отображаемые в память файлы) — самый быстрый способ, но нужна синхронизация;
- **каналы (pipes):** **анонимные** — между родственными процессами, `cmd1 | cmd2`; **именованные (FIFO)** — между любыми процессами;
- **очереди сообщений**;
- **сигналы** — асинхронные уведомления;
- **сокеты** — в том числе между компьютерами по сети;
- **файлы**, **буфер обмена**, сообщения Windows (`WM_COPYDATA`), **RPC / COM**.
</div>

## Зачем нужен обмен

- **Разделение задачи** на части: конвейер обработки, клиент и сервер.
- **Совместное использование** данных: кеш, база данных.
- **Модульность и надёжность**: падение одного процесса не роняет другие (в отличие от потоков).
- Использование **нескольких процессоров**.

## Обмен между потоками

<pre class="diagram">
Процесс
┌────────────────────────────────┐
│ Общая память: глобальные       │
│ переменные, куча, файлы        │
│   ▲            ▲               │
│ Поток 1      Поток 2           │
│ (свой стек)  (свой стек)       │
└────────────────────────────────┘
</pre>

- Потоки **видят одну и ту же память**, поэтому обмен **очень быстрый** и не требует ОС.
- Обязательна **синхронизация** доступа ([вопросы 12–15]({{ '/q/12.html' | relative_url }})). Иначе возникают гонки.
- Типичные схемы: общая **очередь** «производитель–потребитель» с семафорами или условными переменными, **события** для оповещения, потокобезопасные коллекции (`ConcurrentQueue`, `BlockingCollection` в C#).
- **Локальная память потока (TLS)** — данные, приватные для каждого потока.

## Средства IPC

### 1. Разделяемая память (shared memory)

ОС **отображает** один и тот же участок физической памяти в адресные пространства **нескольких процессов**.
- ➕ **Самый быстрый** способ: данные не копируются через ядро.
- ➖ Нужна **отдельная синхронизация** (именованные мьютексы и семафоры).
- **Windows:** `CreateFileMapping` + `MapViewOfFile` (отображаемые в память файлы, в том числе без файла — в файле подкачки). В .NET — `MemoryMappedFile`.
- **UNIX/POSIX:** `shmget`/`shmat` (System V), `shm_open` + `mmap`.

### 2. Каналы (pipes)

**Канал** — однонаправленный поток байтов: один процесс пишет, другой читает (FIFO). ОС буферизует данные и **синхронизирует** стороны автоматически: читатель ждёт, если канал пуст, писатель ждёт, если буфер полон.

- **Анонимные каналы** — только между **родственными** процессами (родитель и потомок наследуют дескрипторы).
  ```bash
  dir | find "txt"        # Windows: вывод dir → вход find
  ls -l | grep ".txt"     # UNIX
  ```
  Системные вызовы: `pipe()` в UNIX, `CreatePipe()` в Windows.
- **Именованные каналы** — имеют имя в системе и доступны **любым процессам**, в Windows даже **по сети**.
  - UNIX: `mkfifo /tmp/myfifo` — специальный файл.
  - Windows: `\\.\pipe\MyPipe`, функции `CreateNamedPipe`, `ConnectNamedPipe`. Каналы Windows могут быть **двунаправленными**.

### 3. Очереди сообщений

Процессы обмениваются **сообщениями** (структурированными порциями данных с типом) через очередь, которую хранит ядро.
- ➕ Сохраняются **границы сообщений**, возможна выборка по типу и приоритету, отправитель и получатель могут работать в разное время.
- UNIX: `msgget`, `msgsnd`, `msgrcv` (System V), `mq_open` (POSIX).
- Windows: очередь сообщений окна (`PostMessage`, `SendMessage`, `WM_COPYDATA`), **MSMQ**.

### 4. Сигналы

**Сигнал** — асинхронное уведомление процесса о событии, «программное прерывание».
- Процесс может обработать сигнал своим обработчиком, игнорировать его или выполнить действие по умолчанию (обычно завершение).
- Примеры UNIX: `SIGINT` (Ctrl+C), `SIGTERM` (просьба завершиться), `SIGKILL` (принудительное завершение, нельзя перехватить), `SIGSEGV` (нарушение памяти), `SIGCHLD` (завершился потомок).
- Команда `kill -9 PID`, системный вызов `kill()`.
- В Windows похожие механизмы — `Ctrl+C` / `GenerateConsoleCtrlEvent` и **события** (`SetEvent`).
- Передают **только факт события**, а не данные.

### 5. Сокеты

**Сокет** — универсальная конечная точка связи. Работает **между процессами на одном компьютере и по сети** (TCP/IP), а также локально (UNIX domain sockets). Подробно: [вопрос 35]({{ '/q/35.html' | relative_url }}).

### 6. Другие способы

- **Файлы** — самый простой способ, но медленный и требует блокировок.
- **Буфер обмена** (Windows clipboard).
- **RPC** (удалённый вызов процедур), **COM/DCOM**, **gRPC**, **D-Bus** в Linux.
- **Почтовые ящики (mailslots)** Windows — широковещательные короткие сообщения.

## Сравнение

| Средство | Направление | Связь процессов | Скорость | Синхронизация | Сеть |
|---|---|---|---|---|---|
| Разделяемая память | Любое | Любые | ★★★ | Нужна отдельная | Нет |
| Анонимный канал | Одно | Родственные | ★★ | Встроенная | Нет |
| Именованный канал | Одно/два | Любые | ★★ | Встроенная | В Windows да |
| Очередь сообщений | Любое | Любые | ★★ | Встроенная | MSMQ — да |
| Сигналы | Одно | Любые | — (без данных) | — | Нет |
| Сокеты | Двунаправленные | Любые | ★ / ★★ | Встроенная | **Да** |

## Две модели обмена

- **Модель разделяемой памяти** — процессы сами читают и пишут общую область. Быстро, но синхронизация на совести программиста.
- **Модель передачи сообщений** — процессы обмениваются сообщениями через ОС (`send`/`receive`): каналы, очереди, сокеты. Проще и безопаснее, подходит для **распределённых систем** ([вопрос 34]({{ '/q/34.html' | relative_url }})).
