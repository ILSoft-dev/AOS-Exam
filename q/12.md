<div class="tldr" markdown="1">
**Синхронизация** — согласование работы потоков, которые используют **общие ресурсы** или **обмениваются данными**. Без неё потоки работают **асинхронно**, с непредсказуемыми относительными скоростями, и возникают ошибки.

**Цели:**
1. **Взаимное исключение** при доступе к разделяемым данным: устранение **гонок (race condition)**.
2. **Согласование по событиям:** один поток ждёт, пока другой выполнит действие (производитель–потребитель).
3. **Обмен данными** между потоками и процессами.

**Средства синхронизации:** **блокирующие переменные** (с командой TSL), **семафоры**, **мьютексы**, **мониторы и условные переменные**, **события**, **сигналы**, **критические секции** (объект Windows), атомарные операции, барьеры. Неправильная синхронизация приводит к **тупикам (deadlock)** и **голоданию**.
</div>

## Почему нужна синхронизация

Потоки выполняются **асинхронно**: ОС может прервать поток в любой момент. Если два потока работают с общими данными, результат зависит от порядка их выполнения. Это **гонки**.

### Классический пример: счётчик

```c
int count = 0;     // общая переменная

void worker(void) {
    for (int i = 0; i < 1000000; i++)
        count++;   // НЕ атомарно!
}
```

Операция `count++` на самом деле состоит из трёх машинных команд: **прочитать** в регистр, **увеличить**, **записать**. Возможный сценарий:

| Поток A | Поток B | count в памяти |
|---|---|---|
| читает count (5) | | 5 |
| ← прерывание | читает count (5) | 5 |
| | увеличивает → 6, записывает | 6 |
| увеличивает → 6, записывает | | **6** (а должно быть 7) |

Если запустить два потока по миллиону итераций, результат почти всегда будет **меньше 2 000 000**, и каждый раз разный.

### Пример с базой данных

Два кассира одновременно снимают деньги с одного счёта: оба прочитали баланс 1000, оба вычли по 300, оба записали 700. Банк потерял 300.

## Основные понятия

- **Разделяемый (критический) ресурс** — ресурс, которым одновременно может пользоваться только один поток.
- **Критическая секция** — часть программы, где поток работает с разделяемыми данными ([вопрос 13]({{ '/q/13.html' | relative_url }})).
- **Взаимное исключение (mutual exclusion)** — в каждый момент в критической секции, связанной с ресурсом, находится не более одного потока.
- **Гонки (race condition)** — ситуация, когда результат зависит от соотношения скоростей потоков.
- **Атомарная операция** — операция, которую нельзя прервать «посередине».

## Задачи синхронизации

1. **Взаимное исключение** — защита общих данных.
2. **Синхронизация по событиям (условиям)** — поток ждёт, пока выполнится условие: данные готовы, буфер не пуст. Классика — **«производитель–потребитель»**.
3. **Проблема читателей и писателей** — читать могут многие одновременно, а писать только один и без читателей ([вопрос 15]({{ '/q/15.html' | relative_url }})).
4. **Обедающие философы** — модель борьбы за несколько ресурсов и тупиков.

## Средства синхронизации (обзор)

| Средство | Идея | Подробно |
|---|---|---|
| **Запрет прерываний** | Поток запрещает прерывания на время критической секции. Годится только для ядра и одного процессора | [Вопрос 13]({{ '/q/13.html' | relative_url }}) |
| **Блокирующие переменные** | Флаг «занято/свободно» + атомарная команда **TSL / XCHG** | [Вопрос 14]({{ '/q/14.html' | relative_url }}) |
| **Семафоры (Дейкстра)** | Целочисленный счётчик с операциями **P (wait)** и **V (signal)**, ожидание без затрат процессора | [Вопрос 15]({{ '/q/15.html' | relative_url }}) |
| **Мьютекс (mutex)** | Двоичный семафор с **владельцем**: освободить может только захвативший поток | [Вопрос 15]({{ '/q/15.html' | relative_url }}) |
| **Монитор** | Конструкция языка: данные + процедуры, в монитор одновременно может войти только один поток. **Условные переменные** (`wait`/`signal`) | `lock` и `Monitor` в C#, `synchronized` в Java |
| **События (events)** | Объект «произошло / не произошло», на котором потоки ждут | `CreateEvent`, `SetEvent` в Windows |
| **Сигналы** | Асинхронное уведомление процесса о событии | `SIGINT`, `SIGTERM` в UNIX |
| **Атомарные операции** | Interlocked-функции, `std::atomic` | `InterlockedIncrement` |
| **Барьеры** | Ждать, пока все потоки дойдут до точки | `pthread_barrier` |

### Синхронизирующие объекты Windows

Ядро Windows предоставляет объекты, находящиеся в состоянии **«свободен» (signaled)** или **«занят» (nonsignaled)**. Поток ждёт их с помощью `WaitForSingleObject` или `WaitForMultipleObjects`:
- **мьютекс** (`CreateMutex`) — взаимное исключение, в том числе между процессами;
- **семафор** (`CreateSemaphore`);
- **событие** (`CreateEvent`) — с ручным или автоматическим сбросом;
- **ожидающий таймер**, а также процесс и поток (становятся «свободны» при завершении).

Объект пользовательского режима **CRITICAL_SECTION** работает быстрее, но только внутри одного процесса.

## Опасности синхронизации

- **Тупик (deadlock, взаимоблокировка)** — потоки бесконечно ждут ресурсы друг друга. Пример: A захватил ресурс R1 и ждёт R2, а B захватил R2 и ждёт R1. Подробно: [тупики]({{ '/extra/deadlocks.html' | relative_url }}).
- **Голодание** — поток бесконечно долго не получает ресурс.
- **Инверсия приоритетов** ([вопрос 8]({{ '/q/08.html' | relative_url }})).
- **Снижение производительности** — слишком «крупные» блокировки уменьшают параллелизм.
