<div class="tldr" markdown="1">
**Виртуализация** — создание **виртуальных (логических) ресурсов** на основе физических. Главное — запуск на одном компьютере **нескольких изолированных виртуальных машин (ВМ)**, каждая со своей **гостевой ОС**.

**Гипервизор (монитор виртуальных машин, VMM)** — программа, которая создаёт ВМ, распределяет между ними ресурсы (процессор, память, устройства) и изолирует их.

**Гипервизор первого типа («bare-metal», «на голом железе»)** работает **непосредственно на оборудовании**, без хостовой ОС. По сути это специализированная ОС для запуска ВМ.
- ➕ Высокая **производительность**, **надёжность** и **безопасность**, малые накладные расходы.
- ➖ Требует отдельного сервера, сложнее в установке, ограниченная поддержка оборудования.
- Применение: **серверы, центры обработки данных, облака**.
- Примеры: **VMware ESXi**, **Microsoft Hyper-V**, **Xen**, **KVM** (часто относят к типу 1), Proxmox VE (на основе KVM).
</div>

**Зачем нужна виртуализация:**
- **консолидация серверов** — много малозагруженных серверов на одном физическом. Экономия денег, места и электроэнергии;
- **изоляция** — сбой или взлом одной ВМ не затрагивает другие;
- **гибкость** — быстрое создание, клонирование, **снимки (snapshots)**, **живая миграция** ВМ между хостами без остановки;
- **отказоустойчивость** и высокая доступность (HA-кластеры);
- запуск **разных ОС** и **устаревших** приложений;
- **тестирование и разработка**, песочницы;
- основа **облачных вычислений** (IaaS).

**Виды виртуализации:** серверов (ВМ), **рабочих столов (VDI)**, приложений, **на уровне ОС (контейнеры** — Docker, LXC: общее ядро, изолированные пространства имён), хранилищ (SAN, SDS), сети (VLAN, SDN).

## Требования Попека и Голдберга (1974)

Монитор виртуальных машин должен обеспечивать:
1. **Эквивалентность** — программа в ВМ ведёт себя так же, как на реальной машине.
2. **Управление ресурсами** — гипервизор полностью контролирует ресурсы.
3. **Эффективность** — большинство команд гостя выполняются **напрямую** на процессоре, без вмешательства гипервизора.

Условие возможности классической виртуализации: все **чувствительные** команды (меняющие состояние машины) должны быть **привилегированными**, то есть вызывать **исключение (trap)** в непривилегированном режиме. Тогда работает схема **«trap-and-emulate»**: гипервизор перехватывает команду и эмулирует её.

Классический **x86 этому условию не удовлетворял**: около 17 чувствительных команд, например `POPF`, не вызывали trap. Решения:
- **двоичная трансляция** (VMware, 1999) — опасные команды гостя заменяются «на лету»;
- **паравиртуализация** (Xen) — гостевая ОС модифицируется ([вопрос 39]({{ '/q/39.html' | relative_url }}));
- **аппаратная поддержка виртуализации** — **Intel VT-x** и **AMD-V** (2005–2006). Появился новый режим процессора «root/non-root». Гостевое ядро работает в своём «кольце 0», а чувствительные команды вызывают **VM exit** в гипервизор.

## Гипервизор первого типа

**Особенности:**
- Загружается **вместо ОС**, напрямую управляет процессором, памятью и (частично) устройствами.
- Содержит планировщик ВМ, менеджер памяти, драйверы или делегирует драйверы служебной ВМ.
- Управляется через **консоль** или удалённо (vCenter, Hyper-V Manager, веб-интерфейс).

### Разновидности архитектуры

- **Монолитный гипервизор:** драйверы устройств находятся **внутри** гипервизора. Пример — **VMware ESXi**. ➕ Быстро. ➖ Нужны специальные драйверы, ограниченный список поддерживаемого оборудования.
- **Микроядерный гипервизор:** гипервизор минимален, драйверы и управление находятся в **привилегированной служебной ВМ**: **родительский раздел (root partition)** в Hyper-V, **Dom0** в Xen. ➕ Используются обычные драйверы ОС, гипервизор меньше и надёжнее.

## Примеры

| Гипервизор | Разработчик | Особенности |
|---|---|---|
| **VMware ESXi (vSphere)** | VMware (Broadcom) | Монолитный, лидер корпоративного рынка, vMotion (живая миграция), HA, DRS |
| **Microsoft Hyper-V** | Microsoft | Микроядерный. Входит в Windows Server и Windows 10/11 Pro. После включения роли сама Windows работает в **родительском разделе** поверх гипервизора |
| **Xen** | Кембридж, Citrix | Микроядерный, Dom0 + DomU. Паравиртуализация. Исторически основа AWS |
| **KVM** | Red Hat, сообщество Linux | Модуль ядра Linux превращает Linux в гипервизор. Используется в Proxmox, OpenStack, Google Cloud, современном AWS (Nitro) |

<div class="tip" markdown="1">
**Hyper-V — тип 1**, хотя устанавливается «из Windows». После включения роли гипервизор загружается **первым**, а Windows становится привилегированной ВМ (родительским разделом). **KVM** формально находится внутри ядра Linux, и его относят то к первому типу (ядро Linux само становится гипервизором), то к «гибридам».
</div>

## Сравнение с типом 2 (кратко)

| | Тип 1 (bare-metal) | Тип 2 (hosted) |
|---|---|---|
| Работает на | Оборудовании | Хостовой ОС |
| Производительность | Выше | Ниже |
| Назначение | Серверы, ЦОД, облака | Рабочие станции, тестирование, обучение |
| Примеры | ESXi, Hyper-V, Xen, KVM | VirtualBox, VMware Workstation, Parallels |
