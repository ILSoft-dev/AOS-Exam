<div class="tldr" markdown="1">
**Способ отображения** определяет, **в какие строки кеша может попасть блок основной памяти** и как его там найти.

1. **Прямое отображение (direct mapped):** каждый блок ОП может находиться **только в одной** строке кеша: строка = (номер блока) mod (число строк). Просто и быстро, но много **конфликтных промахов**.
2. **Полностью ассоциативное (fully associative):** блок может быть в **любой** строке. Нужно сравнивать тег **со всеми строками одновременно**. Минимум конфликтов, но дорого. Применяется в маленьких кешах (TLB).
3. **Множественно-ассоциативное (наборно-ассоциативное, set-associative):** кеш разбит на **наборы** по k строк. Блок отображается в **определённый набор** (как при прямом отображении), а внутри набора — в **любую** строку (как при ассоциативном). Компромисс, используется в процессорах (L1–L3 — 4…16-канальные).

Адрес при этом делится на поля **тег | индекс (строка или набор) | смещение**.
</div>

## Исходные данные для примеров

- Основная память: 64 КБ → адрес **16 бит**.
- Кеш: 1 КБ, строка **16 байт** → **64 строки**.
- Смещение в строке: log₂16 = **4 бита**.

## 1. Прямое отображение

Каждый блок памяти имеет **ровно одно** место в кеше:

**номер строки = номер блока mod число строк**

<pre class="diagram">
Блоки ОП          Кеш (64 строки)
0, 64, 128 … ───► строка 0
1, 65, 129 … ───► строка 1
 …                 …
63,127,191 … ───► строка 63
</pre>

**Разбиение адреса** (16 бит):

<pre class="diagram">
┌────────────┬────────────┬──────────┐
│ Тег 6 бит  │ Строка 6 б │ Смещ. 4 б│
└────────────┴────────────┴──────────┘
   (16−6−4)    (64 = 2⁶)    (16 = 2⁴)
</pre>

**Поиск:** индекс сразу указывает на строку, и сравнивается **один** тег.

**Пример:** адрес 0x1234 = 0001 0010 0011 0100₂ → тег = 000100₂ = 4, строка = 100011₂ = 35, смещение = 0100₂ = 4.

- ➕ Очень **просто и быстро**: один компаратор, не нужен алгоритм замещения.
- ➖ **Конфликтные промахи:** если программа поочерёдно обращается к блокам 0 и 64, они вытесняют друг друга, даже если остальной кеш пуст («пробуксовка» кеша).

## 2. Полностью ассоциативное отображение

Блок может быть загружен в **любую** свободную строку. Тег — это весь номер блока.

<pre class="diagram">
┌──────────────────────┬──────────┐
│      Тег 12 бит      │ Смещ. 4 б│
└──────────────────────┴──────────┘
</pre>

**Поиск:** тег адреса **одновременно** сравнивается с тегами **всех** строк (ассоциативная память). Нужно 64 компаратора.

- ➕ **Нет конфликтных промахов**, максимальный коэффициент попаданий для заданного объёма.
- ➕ Свобода в выборе строки для замещения (LRU).
- ➖ **Дорого и сложно** аппаратно, больше энергопотребление, медленнее при большом числе строк.
- Применение: **TLB**, маленькие специализированные кеши.

## 3. Множественно-ассоциативное (наборно-ассоциативное) отображение

Кеш делится на **S наборов** по **k строк** (**k-канальный кеш**, k-way):

**номер набора = номер блока mod S**, внутри набора — любая из k строк.

Для нашего примера при **k = 4**: S = 64 / 4 = **16 наборов** → индекс набора **4 бита**.

<pre class="diagram">
┌──────────────┬───────────┬──────────┐
│ Тег 8 бит    │ Набор 4 б │ Смещ. 4 б│
└──────────────┴───────────┴──────────┘
</pre>

<pre class="diagram">
Набор 0: [стр][стр][стр][стр]  ← блоки 0,16,32,…
Набор 1: [стр][стр][стр][стр]  ← блоки 1,17,33,…
 …
Набор 15:[стр][стр][стр][стр]
</pre>

**Поиск:** индекс выбирает набор, затем тег сравнивается **параллельно с k строками** набора (k компараторов).

- ➕ Компромисс: конфликтов гораздо меньше, чем при прямом отображении, а аппаратура намного проще, чем при полностью ассоциативном.
- Частные случаи: **k = 1** — прямое отображение, **k = числу строк** — полностью ассоциативное.
- Применение: кеши L1 (8-канальные), L2 и L3 (8–16-канальные) современных процессоров.

## Сравнение

| | Прямое | Множественно-ассоциативное | Полностью ассоциативное |
|---|---|---|---|
| Куда может попасть блок | В 1 строку | В любую из k строк своего набора | В любую строку |
| Поля адреса | Тег, строка, смещение | Тег, набор, смещение | Тег, смещение |
| Сравнений тегов | 1 | k | Все строки |
| Конфликтные промахи | Много | Мало | Нет |
| Нужен алгоритм замещения | Нет | Да (внутри набора) | Да |
| Стоимость и сложность | Низкая | Средняя | Высокая |
| Где используется | Простые и старые кеши | Кеши процессоров L1–L3 | TLB |

## Как рассчитать поля адреса (алгоритм для задач)

1. **Смещение** = log₂(размер строки).
2. **Число строк** = размер кеша / размер строки.
3. **Индекс:**
   - прямое: log₂(число строк);
   - k-канальное: log₂(число строк / k);
   - полностью ассоциативное: 0.
4. **Тег** = разрядность адреса − индекс − смещение.

**Задача:** адрес 32 бита, кеш 32 КБ, строка 64 Б, 8-канальный.
Смещение = 6; строк = 32768 / 64 = 512; наборов = 512 / 8 = 64 → индекс = 6; тег = 32 − 6 − 6 = **20 бит**.
