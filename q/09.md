<div class="tldr" markdown="1">
**Смешанные алгоритмы** сочетают **квантование** и **приоритеты**. Потоки обслуживаются по приоритетам, а внутри одного приоритета — по кругу квантами (Round Robin). Так достигается и **справедливость**, и **быстрая реакция** на важные события.

Основные варианты:
- **Многоуровневые очереди (MLQ):** несколько очередей с разными приоритетами и своими алгоритмами. Поток закреплён за очередью.
- **Многоуровневые очереди с обратной связью (MLFQ):** поток **перемещается** между очередями в зависимости от поведения. Израсходовал квант — опускается ниже (с бо́льшим квантом). Часто уходит на ввод-вывод — остаётся наверху.

Пример — планировщик **Windows**: 32 уровня приоритета, абсолютные приоритеты, RR внутри уровня, динамическое повышение приоритета. В **Linux** — CFS, а с версии 6.6 — EEVDF, плюс классы реального времени.
</div>

## Зачем смешивать

| Только квантование | Только приоритеты |
|---|---|
| ➕ Справедливо, нет голодания | ➕ Важные задачи обслуживаются быстро |
| ➖ Не учитывает важность задач | ➖ Голодание низкоприоритетных, нет разделения времени между равными |

Смешанный подход берёт лучшее из обоих. Большинство современных ОС используют именно его.

## Многоуровневые очереди (Multilevel Queue)

Потоки делятся на **классы**, у каждого класса своя очередь:

<pre class="diagram">
высший │ системные процессы      (RR)
       │ интерактивные           (RR, q=20мс)
       │ пакетные / фоновые      (FIFO)
низший │ студенческие :)         (FIFO)
</pre>

- Между очередями действуют **абсолютные приоритеты**: нижняя обслуживается, только если все верхние пусты. Возможен и вариант с **разделением времени между очередями** (например, 80 % / 20 %).
- **Внутри очереди** работает свой алгоритм: RR для интерактивных и FIFO для пакетных.
- Поток **навсегда закреплён** за своей очередью.

## Многоуровневые очереди с обратной связью (MLFQ)

Самый гибкий классический алгоритм. Поток **не закреплён** за очередью, ОС «учится» на его поведении:

<pre class="diagram">
Очередь 0 (высш.) q = 8 мс   ──┐ не успел
Очередь 1         q = 16 мс  ◄─┘──┐ не успел
Очередь 2 (низш.) FIFO       ◄────┘
</pre>

Правила:
1. Новый поток попадает в **верхнюю** очередь с малым квантом.
2. Если поток **израсходовал весь квант**, он «вычислительный» и переходит в **очередь ниже** с бо́льшим квантом.
3. Если поток **ушёл на ввод-вывод раньше**, он остаётся на своём уровне или поднимается выше: интерактивные задачи получают процессор первыми.
4. Чтобы не было голодания, потоки, долго ждущие внизу, периодически **поднимаются наверх (старение)**.

Итог: короткие и интерактивные задачи завершаются быстро (как в SJF), хотя длительность заранее не известна, а длинные вычислительные задачи всё равно выполняются.

## Планирование в Windows

- Планируются **потоки**, а не процессы.
- **32 уровня приоритета**: 16–31 — реальное время (фиксированные), 1–15 — динамические, 0 — системный поток обнуления страниц.
- **Абсолютные приоритеты:** готовый поток с более высоким приоритетом немедленно вытесняет текущий.
- **Внутри уровня — Round Robin** квантами.
- **Динамика:** повышение приоритета после ввода-вывода, для активного окна, для потоков, давно не получавших процессор (защита от голодания). С каждым квантом добавка снижается.
- На многопроцессорных системах учитываются **идеальный процессор** и **привязка (affinity)** потока к ядрам.

## Планирование в Linux

- **Классы реального времени** `SCHED_FIFO` и `SCHED_RR` (приоритеты 1–99) всегда важнее обычных задач.
- **Обычные задачи** с 2007 года планировал **CFS (Completely Fair Scheduler)**: каждой задаче учитывается «виртуальное время выполнения» `vruntime`, выбирается задача с наименьшим `vruntime`. Задачи хранятся в красно-чёрном дереве. Значение `nice` задаёт вес: чем выше приоритет, тем медленнее растёт `vruntime`. С версии ядра 6.6 (2023) CFS заменён на **EEVDF** с той же идеей справедливого распределения.
- Отдельные очереди готовых задач для каждого ядра, с балансировкой нагрузки.

## Пример: смешанное планирование

Приоритеты: A = 2, B = 2, C = 1 (больше — важнее). Квант 2 мс. Выполнение: A = 4, B = 3, C = 2.

Сначала обслуживаются потоки приоритета 2 по кругу, затем C:

<pre class="diagram">
| A | B | A | B |C |
0   2   4   6  7  9
</pre>

A завершится в 6, B — в 7, C — в 9. Потоку C пришлось ждать, пока закончатся более приоритетные.
