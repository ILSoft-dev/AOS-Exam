<div class="tldr" markdown="1">
**Системный вызов (system call)** — это обращение приложения к ядру ОС за услугой, которую нельзя выполнить в пользовательском режиме: работа с файлами, создание процесса, выделение памяти, ввод-вывод.

Механизм вызова такой:
1. Приложение помещает **номер вызова** и **параметры** в регистры или стек.
2. Выполняется специальная инструкция **программного прерывания / trap**: `int 0x80`, `syscall`, `sysenter`.
3. Процессор переключается в **режим ядра**. Ядро по номеру находит обработчик в **таблице системных вызовов**, проверяет параметры и выполняет работу.
4. Ядро возвращает результат или код ошибки и переключает процессор обратно в пользовательский режим.

Обычно приложение вызывает не системный вызов напрямую, а **функцию библиотеки** (libc, WinAPI), которая делает это за него.
</div>

## Зачем нужны системные вызовы

Приложения работают в **пользовательском режиме** и не имеют прямого доступа к устройствам, чужой памяти и структурам ядра. Это обеспечивает **защиту и стабильность**. Системный вызов — **единственная контролируемая «дверь»** из пользовательского режима в ядро. Набор системных вызовов образует **интерфейс прикладного программирования ОС (API)**.

## Как выполняется системный вызов (пример `read`)

<pre class="diagram">
 Пользовательский режим
 ─────────────────────────────────
 Программа:  n = read(fd, buf, 100)
     │
     ▼
 Библиотека libc: номер вызова → RAX,
 параметры → RDI, RSI, RDX
     │  инструкция syscall (trap)
 ════╪═══════════════════════════ граница
     ▼          Режим ядра
 Диспетчер системных вызовов:
 table[номер] → sys_read()
     │ проверка прав и параметров,
     │ работа с ФС и драйвером
     ▼
 Результат → RAX, возврат (sysret)
 ─────────────────────────────────
 Программа получает n
</pre>

**Способы передачи параметров:** через **регистры** (быстро, Linux x86-64), через **блок или таблицу в памяти** (адрес передаётся в регистре) или через **стек**.

**Стоимость:** системный вызов значительно дороже обычного вызова функции. Нужны переход в режим ядра, сохранение и восстановление регистров, проверки. Поэтому библиотеки **буферизуют** ввод-вывод: например, `printf` копит данные и вызывает `write` реже.

## Категории системных вызовов

| Категория | UNIX/Linux (POSIX) | Windows (WinAPI) |
|---|---|---|
| **Управление процессами** | `fork`, `exec`, `exit`, `wait`, `kill` | `CreateProcess`, `ExitProcess`, `WaitForSingleObject`, `TerminateProcess` |
| **Работа с файлами** | `open`, `read`, `write`, `close`, `lseek` | `CreateFile`, `ReadFile`, `WriteFile`, `CloseHandle`, `SetFilePointer` |
| **Работа с каталогами и ФС** | `mkdir`, `rmdir`, `link`, `unlink`, `mount`, `stat` | `CreateDirectory`, `RemoveDirectory`, `DeleteFile` |
| **Управление устройствами** | `ioctl`, `read`, `write` | `DeviceIoControl` |
| **Информационные** | `getpid`, `time`, `uname` | `GetCurrentProcessId`, `GetSystemTime` |
| **Связь (IPC, сеть)** | `pipe`, `shmget`, `socket`, `send`, `recv` | `CreatePipe`, `CreateFileMapping`, `socket` |
| **Память** | `brk`, `mmap`, `munmap` | `VirtualAlloc`, `VirtualFree` |
| **Защита** | `chmod`, `chown`, `umask` | `SetFileSecurity` |

## Пример на C (Linux)

```c
#include <fcntl.h>
#include <unistd.h>

int main(void) {
    char buf[128];
    int fd = open("data.txt", O_RDONLY);   // системный вызов open
    ssize_t n = read(fd, buf, sizeof buf); // системный вызов read
    write(1, buf, n);                      // write в stdout (дескриптор 1)
    close(fd);                             // close
    return 0;
}
```

Утилита `strace ./prog` в Linux показывает все системные вызовы программы. В Windows для этого есть Process Monitor.

## Создание процесса в UNIX: `fork` + `exec`

- `fork()` создаёт **копию** текущего процесса. Родителю возвращается PID потомка, потомку — 0.
- `exec()` **заменяет** программу текущего процесса новой.
- `wait()` — родитель ждёт завершения потомка.

Так работает командная оболочка: она делает `fork`, а потомок выполняет `exec` введённой команды.

<div class="warn" markdown="1">
Не путайте **системный вызов** и **функцию библиотеки**. `printf` и `fopen` — функции стандартной библиотеки C, а внутри они вызывают `write` и `open`. В Windows приложения используют **WinAPI** (kernel32.dll), который обращается к «родным» вызовам ядра **Native API** (ntdll.dll: `NtCreateFile` и др.).
</div>
