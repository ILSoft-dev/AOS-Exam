<div class="tldr" markdown="1">
**Контроль доступа** определяет, **кто** (субъект — пользователь, группа, процесс) и **какие операции** (чтение, запись, выполнение, удаление, смена прав) может выполнять над **объектом** (файлом, каталогом).

Подходы:
- **Избирательный (дискреционный, DAC):** права назначает **владелец** объекта. Используется в Windows и UNIX.
- **Мандатный (MAC):** объектам и субъектам присвоены **уровни секретности**, доступ определяется правилами системы (SELinux, военные системы).
- **Ролевой (RBAC):** права назначаются ролям.

Модель — **матрица доступа** (субъекты × объекты). Её хранят по столбцам — **списки контроля доступа (ACL)** у объекта, или по строкам — **списки возможностей (capabilities)** у субъекта.

**UNIX:** права **rwx** для трёх категорий: **владелец, группа, остальные** (`chmod 754`). **NTFS:** полноценные **ACL** с записями ACE «разрешить/запретить» для любых пользователей и групп, **наследование** прав (`icacls`).
</div>

## Основные понятия

- **Субъект доступа** — пользователь или процесс, который выполняется от его имени. Каждый пользователь имеет **идентификатор**: UID в UNIX, **SID** в Windows. Пользователи объединяются в **группы**.
- **Объект доступа** — файл, каталог, устройство, разделяемая память…
- **Владелец** — обычно создатель объекта. Он может менять права.
- **Тип доступа (право)** — операция: чтение, запись, выполнение, удаление, изменение прав, смена владельца.
- **Аутентификация** — проверка, что пользователь тот, за кого себя выдаёт (пароль). **Авторизация** — проверка прав на операцию.

## Матрица доступа

|  | report.docx | salary.xlsx | app.exe |
|---|---|---|---|
| **Иванов** | чтение, запись (владелец) | — | выполнение |
| **Петров** | чтение | чтение, запись | выполнение |
| **Бухгалтерия** (группа) | — | чтение | — |

Матрица большая и разреженная, поэтому хранят её по частям:
- **по столбцам — ACL (Access Control List):** у каждого объекта список «кто → какие права». Используется в Windows NTFS и UNIX (rwx — упрощённый ACL).
- **по строкам — списки возможностей (capability list):** у каждого субъекта список объектов, к которым он имеет доступ, и права.

## Избирательный и мандатный доступ

| | Избирательный (DAC) | Мандатный (MAC) |
|---|---|---|
| Кто назначает права | Владелец объекта | Администратор безопасности, политика системы |
| Основа | ACL, матрица доступа | **Метки секретности**: «несекретно» < «ДСП» < «секретно» < «сов. секретно» |
| Правило | Как указано в ACL | Читать можно объекты своего уровня и ниже, писать — своего уровня и выше (модель Белла–Лападулы) |
| Примеры | Windows, UNIX | SELinux, Astra Linux, военные системы |

## Права доступа в UNIX / Linux

Для каждого файла хранятся **владелец (UID)**, **группа (GID)** и **9 бит прав**:

<pre class="diagram">
-rwxr-xr--  1 ivan  staff  4096 report.sh
│└┬┘└┬┘└┬┘
│ │  │  └─ остальные (others): r--
│ │  └──── группа (group):     r-x
│ └─────── владелец (user):    rwx
└───────── тип: - файл, d каталог,
           l ссылка
</pre>

| Право | Для файла | Для каталога |
|---|---|---|
| **r** (4) | Читать содержимое | Просматривать список файлов |
| **w** (2) | Изменять | Создавать и удалять файлы в каталоге |
| **x** (1) | Выполнять как программу | «Входить» в каталог (`cd`), обращаться к файлам по имени |

**Восьмеричная запись:** rwx = 4 + 2 + 1 = 7, r-x = 5, r-- = 4. Значит, `rwxr-xr--` = **754**.

```bash
chmod 754 report.sh        # rwxr-xr--
chmod u+x,g-w file.txt     # символьная форма
chown ivan:staff file.txt  # сменить владельца и группу
umask 022                  # маска прав для новых файлов
ls -l                      # просмотр прав
```

**Специальные биты:**
- **SUID** — программа выполняется с правами **владельца файла** (например, `passwd`);
- **SGID** — с правами группы;
- **sticky bit** на каталоге — удалять файлы может только их владелец (`/tmp`).

**root** (UID 0) имеет доступ ко всему. Дополнительно Linux поддерживает расширенные **POSIX ACL** (`setfacl`, `getfacl`).

## Права доступа в Windows (NTFS)

- Каждый объект имеет **дескриптор безопасности**: владелец, **DACL** (список разрешений) и **SACL** (список аудита).
- DACL состоит из записей **ACE** (Access Control Entry): «SID пользователя или группы — **разрешить / запретить** — набор прав».
- **Стандартные разрешения:** полный доступ, изменение, чтение и выполнение, список содержимого папки, чтение, запись, а также детальные «особые» разрешения.
- **Наследование:** права папки по умолчанию распространяются на вложенные файлы и папки.
- **Правило:** явный **запрет приоритетнее разрешения**. Итоговые права пользователя складываются из его прав и прав всех его групп.
- При проверке система сравнивает **маркер доступа** (access token) процесса, где записаны SID пользователя и групп, с ACL объекта.
- **Права общего доступа** (для сетевых папок) и права NTFS действуют **вместе**: итоговые — **наиболее строгие** из двух.

```text
icacls C:\Data                         — показать ACL
icacls C:\Data /grant Ivan:(OI)(CI)M   — дать Ивану «Изменение» с наследованием
icacls C:\Data /deny Guest:R           — запретить чтение
icacls C:\Data /inheritance:d          — отключить наследование
takeown /F C:\Data /R                  — стать владельцем
attrib +R +H file.txt                  — атрибуты «только чтение», «скрытый»
```

Также используются **UAC** (контроль учётных записей) и **уровни целостности** (Mandatory Integrity Control) — элемент мандатного доступа в Windows.

## Другие механизмы защиты файлов

- **Шифрование:** EFS и BitLocker в Windows, LUKS в Linux.
- **Аудит** доступа (SACL, журнал безопасности).
- **Квоты** — ограничение объёма для пользователя.
- **Атрибуты:** «только чтение», «скрытый», «системный».
