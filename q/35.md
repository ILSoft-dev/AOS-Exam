<div class="tldr" markdown="1">
**Сокет (socket)** — программный интерфейс и **конечная точка двусторонней связи** между процессами, как на одном компьютере, так и **по сети**. Впервые появился в **BSD UNIX (1983)**, в Windows называется **Winsock**.

Сокет характеризуется:
- **доменом (семейством адресов):** `AF_INET` (IPv4), `AF_INET6` (IPv6), `AF_UNIX` (локальный, через файл);
- **типом:** **потоковый (`SOCK_STREAM`, TCP)** — с установлением соединения, надёжный, упорядоченный поток байтов; **дейтаграммный (`SOCK_DGRAM`, UDP)** — без соединения, отдельные сообщения без гарантий доставки; **сырой (`SOCK_RAW`)**;
- **адресом:** **IP-адрес + номер порта**.

Последовательность для TCP: **сервер** — `socket` → `bind` → `listen` → `accept` → `recv`/`send` → `close`; **клиент** — `socket` → `connect` → `send`/`recv` → `close`.
</div>

## Понятие сокета

- Абстракция, **скрывающая детали** сетевых протоколов. Приложение работает с сокетом почти как с файлом: в UNIX сокет — это **файловый дескриптор**, к нему применимы `read` и `write`.
- Соединение TCP однозначно определяется **парой сокетов**: (IP клиента, порт клиента, IP сервера, порт сервера) + протокол.
- **Порт** — 16-битный номер (0–65535), который идентифицирует **процесс или службу** на компьютере:
  - **0–1023** — хорошо известные: 80 HTTP, 443 HTTPS, 22 SSH, 25 SMTP, 53 DNS, 445 SMB, 3389 RDP;
  - **1024–49151** — регистрируемые (например, 1433 MS SQL, 5432 PostgreSQL);
  - **49152–65535** — динамические, их ОС выдаёт клиентам.

## Типы сокетов

| | Потоковый (`SOCK_STREAM`) | Дейтаграммный (`SOCK_DGRAM`) |
|---|---|---|
| Протокол | **TCP** | **UDP** |
| Соединение | Устанавливается (трёхэтапное рукопожатие SYN, SYN-ACK, ACK) | Не устанавливается |
| Надёжность | Гарантированная доставка, порядок, без дубликатов | Без гарантий |
| Единица данных | Поток байтов (границы сообщений не сохраняются) | Дейтаграмма (границы сохраняются) |
| Скорость, накладные расходы | Ниже скорость, больше расходы | Быстро, мало накладных расходов |
| Применение | HTTP, почта, передача файлов, БД, SSH | DNS, потоковое видео и голос, онлайн-игры, DHCP |

**Сырые сокеты (`SOCK_RAW`)** дают доступ к пакетам нижнего уровня (IP, ICMP). Так работают `ping` и анализаторы трафика. Требуют прав администратора.

## Последовательность вызовов (TCP)

<pre class="diagram">
     СЕРВЕР                 КЛИЕНТ
  socket()               socket()
     │                      │
  bind(IP:порт)             │
     │                      │
  listen(очередь)           │
     │                      │
  accept() ◄─── соединение ─ connect(IP:порт)
  (блокируется,             │
   возвращает новый         │
   сокет для клиента)       │
     │                      │
  recv() ◄──── запрос ───── send()
  send() ───── ответ ─────► recv()
     │                      │
  close()                close()
</pre>

| Функция | Назначение |
|---|---|
| `socket()` | Создать сокет (домен, тип, протокол), получить дескриптор |
| `bind()` | Привязать сокет к **локальному адресу и порту** (на сервере обязательно) |
| `listen()` | Перевести сокет в режим **ожидания соединений**, задать длину очереди |
| `accept()` | Принять входящее соединение. Возвращает **новый сокет** для обмена с конкретным клиентом, а слушающий сокет продолжает ждать других |
| `connect()` | (Клиент) установить соединение с сервером |
| `send()` / `recv()` | Передать / принять данные (TCP) |
| `sendto()` / `recvfrom()` | Передать / принять дейтаграмму с указанием адреса (UDP) |
| `close()` / `closesocket()` | Закрыть сокет. `shutdown()` закрывает частично |

**UDP:** сервер — `socket` → `bind` → `recvfrom`/`sendto`; клиент — `socket` → `sendto`/`recvfrom`. Нет `listen`, `accept` и `connect`.

## Пример: TCP-эхо-сервер и клиент на C#

```csharp
using System.Net;
using System.Net.Sockets;
using System.Text;

// Сервер
var listener = new Socket(AddressFamily.InterNetwork,
                          SocketType.Stream, ProtocolType.Tcp);
listener.Bind(new IPEndPoint(IPAddress.Any, 5000)); // bind
listener.Listen(10);                                 // listen
while (true) {
    Socket client = listener.Accept();               // accept
    var buf = new byte[1024];
    int n = client.Receive(buf);                     // recv
    client.Send(buf, n, SocketFlags.None);           // send (эхо)
    client.Close();
}
```

```csharp
// Клиент
var s = new Socket(AddressFamily.InterNetwork,
                   SocketType.Stream, ProtocolType.Tcp);
s.Connect("127.0.0.1", 5000);                        // connect
s.Send(Encoding.UTF8.GetBytes("Привет"));
var buf = new byte[1024];
int n = s.Receive(buf);
Console.WriteLine(Encoding.UTF8.GetString(buf, 0, n));
s.Close();
```

Для простых задач в .NET есть обёртки `TcpListener`/`TcpClient` и `UdpClient`.

## Блокирующий и неблокирующий режимы

- По умолчанию `accept`, `recv` и `connect` **блокируют** поток до наступления события.
- Чтобы обслуживать много клиентов:
  - **поток на каждого клиента** — просто, но плохо масштабируется;
  - **неблокирующие сокеты + мультиплексирование**: `select`, `poll`, `epoll` (Linux), **IOCP** (порты завершения ввода-вывода в Windows);
  - **асинхронные** методы: `async`/`await`, `AcceptAsync`, `ReceiveAsync` в C#.

## Сокеты в ОС

- В UNIX сокет — **файловый дескриптор**. Есть локальные **UNIX domain sockets** (`AF_UNIX`), которые работают через файл в ФС и быстрее TCP на одной машине.
- **Windows Sockets (Winsock)** — реализация в Windows (`ws2_32.dll`). Перед использованием нужен вызов `WSAStartup()`. С Windows 10 поддерживается и `AF_UNIX`.
- Просмотр открытых соединений и портов: `netstat -ano` (Windows), `ss -tulpn` (Linux).
