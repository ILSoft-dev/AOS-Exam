<div class="tldr" markdown="1">
**Семафор** (Э. Дейкстра, 1965) — целая **неотрицательная переменная S** с двумя **неделимыми** операциями:
- **P(S)** (*proberen* — проверить; wait, down): если S > 0, то S := S − 1 и поток продолжает работу, иначе поток **блокируется** и ждёт, пока S не станет больше 0.
- **V(S)** (*verhogen* — увеличить; signal, up, post): S := S + 1. Если есть ждущие потоки, один из них **будится**.

Виды: **двоичный** (0/1, для взаимного исключения), **считающий** (для учёта N однотипных ресурсов). **Мьютекс** — двоичный семафор с владельцем.

Ожидание **пассивное**: поток спит и не тратит процессор. Классические задачи: **производитель–потребитель** (3 семафора: `mutex`, `empty`, `full`) и **читатели–писатели**. Неправильный порядок операций P может привести к **тупику**.
</div>

## Операции

```text
P(S):  если S > 0 то S := S − 1
       иначе поток → очередь ожидания семафора S

V(S):  если очередь S не пуста
           разбудить один поток (→ готовность)
       иначе S := S + 1
```

Неделимость P и V обеспечивает ОС: внутри них используются запрет прерываний или спин-блокировки ([вопрос 14]({{ '/q/14.html' | relative_url }})).

**Смысл значения S:** количество **свободных единиц ресурса**. Ожидающие потоки стоят в очереди, связанной с семафором.

## Взаимное исключение с помощью семафора

```text
семафор mutex = 1

Поток:
    P(mutex)
    критическая секция
    V(mutex)
```

Первый поток уменьшает `mutex` до 0 и входит. Второй выполняет P(0) и блокируется. После V первого потока второй просыпается.

## Виды семафоров

| Вид | Значения | Применение |
|---|---|---|
| **Двоичный** | 0 и 1 | Взаимное исключение |
| **Считающий (общий)** | 0…N | Пул из N ресурсов: N принтеров, N соединений с БД, N ячеек буфера |
| **Мьютекс** | Свободен / захвачен + **владелец** | Взаимное исключение. Освободить может **только захвативший поток**, допускается повторный захват (рекурсия) |

## Задача «производитель–потребитель» (ограниченный буфер)

Производитель кладёт элементы в буфер из N ячеек, потребитель забирает. Условия: нельзя класть в полный буфер, нельзя брать из пустого, и с буфером одновременно работает только один поток.

```text
семафор mutex = 1   // доступ к буферу
семафор empty = N   // число пустых ячеек
семафор full  = 0   // число заполненных ячеек

Производитель:                Потребитель:
  loop                          loop
    item = произвести()           P(full)    // есть что брать?
    P(empty)  // есть место?      P(mutex)
    P(mutex)                      item = взять()
    положить(item)                V(mutex)
    V(mutex)                      V(empty)   // стало +1 место
    V(full)   // +1 элемент       потребить(item)
```

<div class="warn" markdown="1">
**Порядок P важен!** Если производитель сделает `P(mutex)` **до** `P(empty)` при полном буфере, он заснёт, удерживая `mutex`. Потребитель не сможет войти и освободить место. Получится **тупик**. Сначала ждём ресурс-условие, потом захватываем мьютекс.
</div>

## Проблема читателей и писателей

С общими данными (например, базой данных) работают:
- **читатели** — могут работать **одновременно**, так как ничего не меняют;
- **писатели** — нужен **монопольный** доступ, без других писателей и без читателей.

Решение с приоритетом читателей:

```text
семафор db = 1        // доступ к данным
семафор mutex = 1     // защищает rc
int rc = 0            // число активных читателей

Писатель:                Читатель:
  P(db)                    P(mutex)
  записать                 rc = rc + 1
  V(db)                    если rc == 1 то P(db)   // первый читатель блокирует писателей
                           V(mutex)
                           читать
                           P(mutex)
                           rc = rc − 1
                           если rc == 0 то V(db)   // последний открывает
                           V(mutex)
```

- ➖ При постоянном потоке читателей **писатель может голодать**. Есть варианты с приоритетом писателей и «справедливые» варианты.
- В ОС для этого есть готовые **блокировки чтения-записи**: `SRWLOCK` в Windows, `pthread_rwlock` в POSIX, `ReaderWriterLockSlim` в C#.

## Семафоры в ОС и языках

**Windows:**
```c
HANDLE s = CreateSemaphore(NULL, 3, 3, NULL); // начальное 3, максимум 3
WaitForSingleObject(s, INFINITE);             // P
/* работа с одним из 3 ресурсов */
ReleaseSemaphore(s, 1, NULL);                 // V
```
Мьютекс: `CreateMutex` / `WaitForSingleObject` / `ReleaseMutex`.

**POSIX:** `sem_init`, `sem_wait` (P), `sem_post` (V). Мьютекс: `pthread_mutex_lock` / `unlock`.

**C#:** `SemaphoreSlim sem = new SemaphoreSlim(3); sem.Wait(); … sem.Release();`, `Mutex`.

## Достоинства и недостатки

- ➕ Универсальность: и взаимное исключение, и синхронизация по событиям.
- ➕ Нет активного ожидания.
- ➖ Легко ошибиться: забыть V, перепутать порядок P. Такие ошибки приводят к тупикам и трудно отлаживаются. Поэтому придуманы **мониторы**: `lock` в C# и `synchronized` в Java автоматически освобождают блокировку.
