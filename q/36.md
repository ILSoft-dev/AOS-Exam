<div class="tldr" markdown="1">
**Сетевая (распределённая) файловая система** даёт пользователям доступ к **файлам на удалённых компьютерах** так, будто они **локальные** (**прозрачность**).

Состав: **сервер** — экспортирует (предоставляет в общий доступ) каталоги; **клиент** — подключает (монтирует) их; **протокол** — правила обмена сообщениями.

Модели доступа:
- **загрузка-выгрузка (upload/download)** — файл целиком копируется на клиент, а после работы отправляется обратно;
- **удалённый доступ** — клиент посылает отдельные запросы (читать N байт, записать) и работает с файлом на сервере.

Важные проблемы: **кеширование и согласованность** копий, **семантика разделения файлов** (UNIX, сеансовая, неизменяемые файлы), **отказоустойчивость** (сервер без состояния или с состоянием), **безопасность**.

Примеры: **NFS** (Sun, UNIX/Linux), **SMB/CIFS** (Windows: «общие папки» `\\server\share`), **DFS** (распределённое пространство имён Windows), AFS, а также облачные хранилища.
</div>

## Архитектура

<pre class="diagram">
 Клиент                          Сервер
┌──────────────┐               ┌──────────────┐
│ Приложение   │               │              │
│  open/read   │               │ Локальная ФС │
│      ▼       │               │ (NTFS, ext4) │
│ VFS / редир. │               │      ▲       │
│      ▼       │  запросы      │ Сервер NFS / │
│ Клиент NFS / │ ────────────► │ служба SMB   │
│ SMB          │ ◄──────────── │              │
└──────────────┘  ответы       └──────────────┘
</pre>

- На клиенте сетевая ФС встраивается через **виртуальную файловую систему (VFS)** в UNIX или **редиректор** в Windows. Приложения используют обычные системные вызовы и не знают, что файл удалённый.
- Сервер работает поверх **своей локальной ФС**.

## Модели доступа

| | Загрузка-выгрузка | Удалённый доступ |
|---|---|---|
| Как работает | Файл копируется на клиент целиком, работа идёт локально, затем файл возвращается | Каждая операция (read, write, seek) — запрос к серверу |
| ➕ | Простота, быстрая работа после загрузки | Не нужно копировать весь файл, данные всегда на сервере |
| ➖ | Нужно место на клиенте, долго для больших файлов, сложно при совместной работе | Много сетевых обменов (решается кешированием) |
| Пример | FTP, ранние AFS, облачная синхронизация | NFS, SMB |

## Кеширование и согласованность

Чтобы не обращаться к серверу при каждой операции, клиенты **кешируют** данные и атрибуты файлов. Возникает проблема **согласованности**: клиент A изменил файл, а у клиента B в кеше старая копия.

Решения:
- **сквозная запись** на сервер + проверка актуальности кеша (по времени модификации);
- **ограниченное время жизни кеша** (NFS: атрибуты кешируются на несколько секунд);
- **уведомления от сервера** об изменениях (обратные вызовы, **callback**, в AFS);
- **блокировки с арендой (oplocks, leases)** в SMB — сервер разрешает клиенту кешировать файл, пока другой клиент его не откроет.

### Семантика разделения файлов

- **Семантика UNIX** — любое чтение возвращает результат **последней** записи. В распределённой системе её трудно обеспечить.
- **Сеансовая семантика** — изменения видны другим только **после закрытия** файла (AFS).
- **Неизменяемые файлы** — файлы нельзя изменять, только создавать новые версии.
- **Транзакции** — операции выполняются атомарно.

## Сервер с состоянием и без состояния

| | Без состояния (stateless) | С состоянием (stateful) |
|---|---|---|
| Что хранит сервер | Ничего о клиентах. Каждый запрос самодостаточен: «прочитать 4 КБ из файла X со смещения Y» | Таблицу открытых файлов, позиции, блокировки |
| ➕ | **Отказоустойчивость**: после перезагрузки сервера клиенты просто повторяют запросы | Короче сообщения, есть блокировки, кеширование с уведомлениями |
| ➖ | Нет блокировок файлов (нужен отдельный механизм) | После сбоя сервера состояние теряется |
| Пример | NFS v2, v3 | NFS v4, SMB |

## NFS (Network File System)

- Разработана **Sun Microsystems** (1984). Стандарт для UNIX и Linux.
- Основана на **RPC** ([вопрос 34]({{ '/q/34.html' | relative_url }})). Версии 2 и 3 — **без состояния**, версия 4 — **с состоянием**: блокировки, безопасность Kerberos, один порт 2049.
- **Сервер** описывает экспортируемые каталоги в `/etc/exports`:
  ```text
  /srv/share   192.168.1.0/24(rw,sync)
  ```
- **Клиент** монтирует каталог в своё дерево:
  ```bash
  mount -t nfs server:/srv/share /mnt/share
  ```
- Права проверяются по UID/GID (в v4 возможен Kerberos).

## SMB / CIFS

- **SMB (Server Message Block)** — протокол **Windows** для доступа к файлам, принтерам и именованным каналам. **CIFS** — диалект SMB 1.0. Сейчас используются **SMB 2.x и 3.x**: быстрее, с шифрованием, multichannel. SMB 1 считается **небезопасным** и отключён.
- Порт **445/TCP**.
- **С состоянием**: открытые файлы, блокировки, **oplocks/leases** для кеширования.
- Имена в формате **UNC**: `\\Server\Share\path\file.txt`.
- В Linux есть сервер и клиент **Samba**.
- Команды Windows:
  ```text
  net share Docs=C:\Docs /grant:Все,READ   — открыть общий доступ
  net share                                — список общих ресурсов
  net use Z: \\server\Docs                 — подключить сетевой диск
  net use Z: /delete                       — отключить
  ```
  Подробнее: [команды Windows]({{ '/cmd.html' | relative_url }}).
- Права: итоговые = **наиболее строгие** из прав общего доступа и прав NTFS.

## DFS (Distributed File System, Windows)

- Единое **пространство имён** `\\domain\dfs\...`, объединяющее общие папки **разных серверов**.
- **Репликация (DFS-R)** папок между серверами: отказоустойчивость и доступ к ближайшей копии.

## Другие системы

- **AFS / Coda** — глобальное пространство имён, кеширование целых файлов на клиенте, сеансовая семантика.
- **Кластерные и распределённые ФС:** HDFS (Hadoop), Ceph, GlusterFS, Lustre.
- **Облачные хранилища:** OneDrive, Google Drive, Яндекс Диск — модель загрузки-выгрузки с синхронизацией. **S3** — объектное хранилище.

## Требования к сетевым ФС

**Прозрачность** (доступа, расположения, репликации), **производительность**, **масштабируемость**, **отказоустойчивость**, **согласованность**, **безопасность** (аутентификация, шифрование), **неоднородность** (разные ОС).
